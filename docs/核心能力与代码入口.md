# 核心能力与代码入口

> 只回答一个问题：
> **遇到某个机制问题，第一段代码打开哪里？**

---

# 1. Single-Agent 主链只记 8 个 Owner

```text
Harness.run
↓
AgentLoop.run
↓
RunPreparation.prepare_run
↓
TurnPreparation.prepare_turn
↓
ModelGateway.chat
↓
ToolExecutionPipeline._execute_call
↓
FinalAnswerBuilder.build_stop_request
↓
RunLifecycle.finalize_run
```

| Owner | 只负责什么 |
|---|---|
| `Harness.run` | Public API、运行产物、ExecutionEnvironment、Runtime 装配 |
| `AgentLoop.run` | 主循环和唯一控制流 |
| `RunPreparation.prepare_run` | 首轮前 clarification / Skill / Memory / resume seed |
| `TurnPreparation.prepare_turn` | 当前 Turn 的 LLM input snapshot |
| `ModelGateway.chat` | Provider / retry / usage |
| `ToolExecutionPipeline._execute_call` | Tool governance 主链 |
| `FinalAnswerBuilder` | 模型最终文本 → typed stop candidate |
| `RunLifecycle.finalize_run` | durable final state |

# 2. 最重要的数据结构

| 问题 | 首个对象 | 必须讲清 |
|---|---|---|
| 整个 Run 状态放哪 | `AgentRunSession` | 跨 Turn live state |
| WorkingMemory 是什么 | `WorkingMemory` | Session 内 bounded task-state view |
| 当前模型到底吃什么 | `PreparedTurn` | `turn_system_message + llm_messages + tool_schemas` |
| 历史超限后是什么 | `ConversationHistoryDigest` | old Conversation projection，不是 Session dump |
| Crash 怎么继续 | `TaskCheckpoint` | execution snapshot + historical projection |
| Tool 返回什么 | `Observation` | typed execution fact |
| ToolCall 怎么治理 | `OperationIntent` | operation identity + side-effect semantics |
| 最终证据怎么引用 | `EvidenceLedger` | final-answer grounding view |

# 9. 评测 / Evaluation

```text

↓
Case Executor
↓
predictions
↓

↓
result / scorecard
```

实验结论必须区分：

```text
candidate patch
local validation
official resolved
infra invalid
```

不要把本地 compile/test 直接升格成 official pass。

# 10. 现场查代码原则

不要：

```text
grep 整个项目
→ 找 20 个类
→ 从 adapter/UI 开始读
```

要：

```text
先问“谁拥有这个业务判断？”
↓
打开 Application / Domain Owner
↓
再追 Port / Adapter
↓
最后用 test / trace 验证
```

这也是 NanoHarness 代码阅读最稳定的方式。
