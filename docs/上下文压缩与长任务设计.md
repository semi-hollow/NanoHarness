# 上下文压缩与长任务设计

> 核心结论：`conversation.jsonl` 是无损事件历史；`ConversationHistoryDigest` 是可重建的 continuation projection；模型每次看到 `stable Turn context + digest + recent raw tail`。

## 1. 问题与边界

长任务会不断追加 User Message、ToolCall 和 Tool Observation，但 Provider context window 有限。简单截断可能拆开 ToolCall 与 Observation，也可能让当前 Turn 的用户约束永久退出模型可见上下文。

NanoHarness 因此把三件事分开：

```text
conversation.jsonl             = raw authority
ConversationHistoryDigest     = deterministic continuation projection
uncovered Conversation tail   = recent exact events
```

核心边界是 `Event history != durable continuation state`。旧 `read_file` 的完整返回是可重建事件；“不要修改 public API”是当前 Turn 的 human authority；某个测试目标的最新结果是 validation state。三者不能使用同一种 retention 规则。

当前方案不判断很久以前某句源码是否仍有语义价值，也不引入 LLM summarization、embedding 或 BM25。

## 2. 一个完整例子

Turn A 的 canonical root task 是：

```text
用户：修 auth refresh bug
Agent：read auth.py
Agent：grep refresh
用户 clarification：不要修改 public API
Agent：edit auth.py
Agent：python_validation(pytest, tests/test_auth.py) -> FAIL
Agent：edit auth.py
Agent：python_validation(pytest, tests/test_auth.py) -> PASS
Agent：git diff
```

这些事件全部 append 到 `conversation.jsonl`。压缩后的 continuation projection 可以是：

```text
Turn.root_task:
- 修 auth refresh bug

current_turn_authority_updates:
- 不要修改 public API

validation_state:
- [passed] python_validation pytest tests/test_auth.py

resource_hints:
- auth.py
- tests/test_auth.py

recent_tool_transactions:
- edit auth.py
- python_validation FAIL
- edit auth.py
- python_validation PASS
- git diff
```

最早的 `read_file` Observation 可以退出 projection：当前 workspace 才是代码状态权威，必要时应重新 read/grep。“不要修改 public API”不能被位置规则淘汰，因为它是当前 Turn authority。早期 FAIL 被同 key 的 PASS 覆盖，因为 continuation 需要最新已知状态，不是测试执行年表。

## 3. 三个持久化对象

### 原始对话：`conversation.jsonl`

`ConversationThreadRepository` 按 sequence 追加 canonical Conversation item，并维护 hash chain。Compaction 不删除、改写或重排它。

### 上下文状态：`context_state.json`

`ThreadContextState` 持久化：

```text
revision
covered_sequence
conversation_history_digest
turn_snapshots[]
```

- `covered_sequence` 是 raw journal 的 compaction cursor；正常 Model Step 只加载它之后的 delta。
- `revision` 是整个 Context State 的 CAS version，不是 Conversation sequence。
- digest 可以跨 Turn 继续保留 validation state 和 recent breadcrumbs，但 authority 通过 `authority_turn_id` 显式归属当前 Turn。
- `turn_snapshots[]` 保存 same-Turn resume 所需的 stable input，包括 canonical root task。

### 运行恢复指针：`TaskCheckpoint`

Checkpoint 只保存 `context_revision` pointer，不复制 digest。Model Step 准备时若 Session 引用的 revision 与 Context State 不一致，则在调用模型前 fail closed。

## 4. 一次真实压缩如何发生

入口是 `ModelStepPreparation.prepare_model_step()`：

```text
load ThreadContextState
-> verify context_revision
-> restore previous digest
-> read journal after covered_sequence
-> transaction-safe segmentation
-> rolling prefix candidate search
-> build delta digest
-> merge previous digest
-> CAS persist context_state.json
-> return final llm_messages
```

假设：

```text
covered_sequence = 850
previous digest covers 1..850
raw journal delta = 851..1000
```

Repository 只读取 850 之后的 items，再分成不可拆 segment `S1, S2, S3 ...`。普通 Message 通常是一个 segment；一个 Assistant ToolCall batch、全部对应 Tool Observations，以及可能的 `ask_human` answer 属于同一个 segment。

超过 soft budget 时，`PromptWindowManager.prepare()` 按顺序尝试：

```text
candidate 1 = previous digest + digest(S1)      + raw(S2..)
candidate 2 = previous digest + digest(S1..S2) + raw(S3..)
candidate 3 = previous digest + digest(S1..S3) + raw(S4..)
```

实现使用 rolling delta：每个新 segment 只调用一次 `_build_digest()`，再通过 `_merge_digest()` 累加，不为每个 candidate 重算 `S1..Sn`。每次都对 System Context、digest、recent tail、transient Runtime messages、Tool schemas 和 reserved output 做完整 token 估算。

第一个满足预算且确实缩小 prompt 的 candidate 就是最小可行 compact prefix。Forced compaction 使用更保守的 tuning target，但仍不拆 transaction。

成功后：

```text
covered_sequence: 850 -> compacted prefix 的最大 raw sequence
digest: previous + delta
revision: r -> r + 1 after CAS
```

下一 Step 从 `context_state.json` 直接恢复 digest，不重读、不重算已 covered prefix。超过一页时，Runtime 按页 rolling merge 并 CAS 推进 cursor，追到最新 tail 后才构造最终 Model request。

## 5. Digest 的 retention policy

V3 核心结构：

```text
ConversationHistoryDigest
├── authority_turn_id
├── authority_updates[]
├── resource_hints[]
├── state_evidence[]
├── recent_tool_transactions[]
├── covered_message_count
├── source_hash
└── token estimates / workspace mutation flag
```

### 当前 Turn authority

`Turn.root_task` 是初始任务的唯一 owner，digest 不再复制 `initial_task`。Stable context builder 会把完整 root task 放入冻结的 `current_turn_root_task` block；若稳定预算无法容纳完整 root task，则 fail closed，不静默截断。`authority_updates` 只接收：

```text
role=user
AND human_authority=true
AND message.turn_id == current_turn_id
AND message.item_id != Turn.input_item_id
```

这些是当前 Turn 执行期的 clarification 或 operator steer。每条可做 deterministic excerpt，但不使用 first/last 数量规则删除整条 authority。如果 authority projection 超过预留容量，Runtime 返回 `authority_context_overflow`，不猜哪条约束更重要。

### 结构化 validation state

只有具有明确结构化 contract 的 `python_validation` 产生 durable state：

```text
identity = tool_name + check_type + validation_target
status   = passed | failed | blocked | unknown | stale
```

`PythonValidationTool` 在 `Observation.validation_status` 中显式返回 passed/failed/blocked；Compaction 不解析 Observation 文本，也不从 ToolRouter 的 `capability/mode` 推断 retention。同 key latest-value-wins，不同 target 独立。

成功的 workspace write 会把已有 validation state 标为 `stale`。它表示“需要重新验证”，不是 failure。V3 不再维护 `unresolved_failures` 这个第二概念，模型直接读取唯一的 `state_evidence`。

Generic `run_command` 只作为 recent breadcrumb。即使 ToolRouter 为工具可见性将它归类为 command/validate，它也不会进入 durable state。ToolRouter 治理“模型能否看到工具”，Compaction 治理“历史保留什么”，两者不共享这个 authority。

### Recent breadcrumbs 与 resource hints

`recent_tool_transactions` 只保留 latest-N 工具意图和结果 excerpt，帮助从 recent tail 继续。N 是 POC tuning parameter，不是“N 条足以构成长程记忆”的假设。

`resource_hints` 只从少量明确 Tool arguments 提取 path、validation target 或 keyword，去重后保留 recent unique 小集合。它不分析 Observation、不做 semantic ranking，只帮助 Agent 在当前 workspace 重新发现资源。

具体 latest-N、字符上限和 forced target 都是可测试的 POC tuning/safety 参数，不是架构不变量。真正的不变量是 ownership、transaction boundary、latest-state-wins 与 fail-closed policy。

## 6. 新 Turn 与 Resume

同一 Thread 创建 Turn B：

```text
Turn B.root_task = 再补 regression test
```

Model Step 发现 previous digest 的 `authority_turn_id` 是 Turn A 时，会将 projection retarget 到 Turn B 并清空 Turn A `authority_updates`。Turn A 的 root task 和 clarification 仍在 raw journal，但不再是 Turn B 的 non-droppable authority。Turn B root task 由 `Turn.root_task` / stable snapshot 直接提供，不在 digest 中复制。

Same-Turn resume 恢复的是显式 durable state：

```text
same Thread + same Turn + new Run
-> restore StableTurnContextSnapshot
-> verify TaskCheckpoint.context_revision
-> restore digest from context_state.json
-> load only journal after covered_sequence
-> continue rolling compaction if needed
```

它不恢复 Python stack、Provider KV cache 或隐藏模型状态，也不重算已覆盖 digest。

## 7. 明确 trade-off

当前 deterministic POC 承诺：

1. raw Conversation 不因 compaction 丢失；
2. 当前 Turn human authority 不按位置静默丢失；
3. 明确 validation contract 的 latest state 不按位置静默丢失；
4. generic 可重建 event history 允许退出 continuation projection；
5. workspace / git diff 是 code state authority；
6. deterministic projection 超出容量时 fail closed。

它不伪装成 arbitrary long-horizon semantic memory。如果未来产品真正需要任意旧 Observation 的语义召回，可以在相同 raw/projection 边界之后增加 governed semantic compaction 或 retrieval；当前不使用 heuristic soup 模拟它。

## 核心源码入口

1. `agent_forge/context/domain/conversation_digest.py`：V3 digest 与两种 Tool projection。
2. `agent_forge/context/application/compaction.py::PromptWindowManager.prepare()`：切分、rolling candidate 与预算决策。
3. 同文件 `_build_digest()` / `_merge_digest()`：新 delta 提取与 deterministic merge。
4. `agent_forge/runtime/application/model_step_preparation.py::prepare_model_step()`：分页追赶、CAS 持久化和最终 `llm_messages`。
5. `agent_forge/runtime/domain/thread.py::ThreadContextState`：cursor、revision、digest 与 stable snapshot 边界。
6. `agent_forge/runtime/adapters/thread_json.py::JsonConversationThreadRepository`：append-only journal 与 Context State persistence。
