# 上下文压缩与长任务设计

> Prompt Window 的职责是把完整 Conversation History 变成当前模型调用可接受、可解释
> 的消息视图，同时保留最近原始交互和工具协议边界。

# 1. 为什么压缩

模型请求同时包含：

```text
turn_system_message
+ conversation history
+ tool schemas
+ reserved output budget
```

随着 Turn 增加，历史会挤占输入窗口。直接截断会破坏因果关系，尤其可能拆开：

```text
assistant ToolCall
↔
tool Observation
```

`PromptWindowManager` 因此先估算完整请求，再在安全事务边界上压缩旧历史。它治理
当前模型视图，不修改 live Session 的原始会话历史；Trace 只记录窗口与压缩投影事实。

# 2. 什么时候压缩

```text
PromptWindowRequest
    ↓
estimate_prompt_tokens()
    ↓
within soft_input_limit and not forced?
    ├── yes → raw system + raw history
    └── no  → attempt safe compaction
```

两种触发来源：

1. 估算输入超过 `PromptBudget.soft_input_limit`；
2. Provider 明确返回 context overflow，`AgentLoop` 以
   `force_compaction=True` 构造一次更小窗口。

强制恢复只有在新窗口的估算 token 确实下降时才允许再次调用模型，避免原请求盲重放。

# 3. 压缩后留下什么

```text
raw Conversation History
    ↓ group protocol-safe segments
old segments                    recent segments
    ↓                                 │
ConversationHistoryDigest             │
    └──────────────┬──────────────────┘
                   ↓
turn_system_message
+ digest system message
+ recent raw tail
                   ↓
PromptWindowResult.llm_messages
```

`ConversationHistoryDigest` 保留：

- initial task；
- 后续 task updates；
- ToolCall / Observation 事务及失败事实；
- 被覆盖消息数量和 source hash；
- 压缩前后的 token 估算。

它不是 Session dump，也不包含当前 Turn System Context。

# 4. 安全压缩边界

`PromptWindowManager.prepare()` 依次完成：

```text
1. 估算完整请求
2. 将历史按协议事务分组
3. 逐步扩大旧历史覆盖范围
4. 保留最近 raw tail
5. 选择满足目标且实际更小的候选
6. 无安全收益时明确返回未压缩结果
```

系统不变量：

- System Message 始终保留；
- assistant ToolCall 和后续 tool Message 不拆分；
- 只有估算输入真正变小才声明 `compacted=True`；
- 无安全边界时返回明确 reason，不伪称已满足 hard limit；
- Tool schemas 参与完整请求估算。

# 5. 后续 Turn 如何继续

```text
PromptWindowResult
    ├── llm_messages → PreparedTurn → ModelPort.chat(...)
    └── conversation_history_digest?
              ↓
       TaskCheckpointUpdate
```

Digest 进入 checkpoint 只是 historical projection。当前
`AgentRunSession.messages` 仍保存原始 Conversation；下一 Turn 会基于当前 Session
重新做窗口决策，而不是在上一次 `PromptWindowResult` 上继续修改。

如果 Run 因 pause/crash 需要继续：

```text
TaskCheckpoint
→ summarize_checkpoint()
→ new continuation AgentRunSession
```

这条路径恢复显式持久化状态，不恢复旧进程内窗口对象。

# 6. 与 WorkingMemory 的区别

```text
Prompt Window compaction
= 控制当前 Model request 的 Conversation 体积

WorkingMemory compaction
= 控制当前 Run 最近任务事实的有界视图

TaskCheckpoint summary
= 为 continuation 提供显式恢复摘要
```

三个机制解决不同生命周期的问题，不共享一个隐式 “memory summary”。

# 7. 设计边界

- Token 估算是调用前近似值，Provider usage 是调用后权威值；
- 当前 compaction 由预算或明确 overflow 触发，不声称进行自然语言重要性分类；
- 压缩只影响当前请求视图，不改变 append-only evidence；
- deadline、side-effect replay 和 no-progress detection 分别由 Runtime budget、
  Operation Ledger 与 StepController 管理，不属于 Prompt Window。

## 源码入口（Source Anchors）

- `agent_forge/context/application/compaction.py::PromptWindowManager.prepare()`：窗口决策主链。
- `agent_forge/context/application/compaction.py::PromptBudget`：输入与输出预留预算。
- `agent_forge/context/application/compaction.py::PromptWindowRequest`：压缩前输入契约。
- `agent_forge/context/application/compaction.py::PromptWindowResult`：模型消息与压缩证据。
- `agent_forge/context/domain/conversation_digest.py::ConversationHistoryDigest`：旧历史投影。
- `agent_forge/runtime/application/turn_preparation.py::TurnPreparation.prepare_turn()`：窗口治理调用方。
- `agent_forge/runtime/application/agent_loop.py::AgentLoop._run_turn()`：overflow 后有界恢复。
