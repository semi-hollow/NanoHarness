# 上下文压缩与长任务设计

> `conversation.jsonl` 保存无损事件历史；`ConversationHistoryDigest` 保存已压缩前缀的确定性 continuation state；模型看到 stable Turn context、digest 与 protocol-preserving recent tail。

# 1. 系统角色与核心契约

长任务持续追加 User Message、ToolCall 和 Tool Observation，而 Provider window 有限。NanoHarness 将 raw authority 与模型投影分开：

```text
conversation.jsonl             lossless raw authority
ConversationHistoryDigest     deterministic compacted-prefix projection
uncovered Conversation tail   protocol-preserving recent projection
```

Protocol-preserving 表示 Message 以及 assistant ToolCall batch 与对应 Tool Observations 不会被拆开；超大正文仍可能 deterministic truncate。无损承诺只属于 `conversation.jsonl`。

Digest 把 event history 分成三类 continuation 信息：当前 Turn 的 human authority、明确的 validation current state、有界 recent breadcrumbs。可从 workspace 重建的旧 read/search/write receipts 可以逐渐退出模型投影。

# 2. 一个完整任务样例

```text
Turn A root task: 修 auth refresh bug

read auth.py
grep refresh
human clarification: 不要修改 public API
edit auth.py
python_validation(pytest, tests/test_auth.py) -> FAIL
edit auth.py
python_validation(pytest, tests/test_auth.py) -> PASS
git diff
```

所有事件按顺序 append 到 journal。某次 compaction 后，模型可见的 digest 近似为：

```text
current_turn_authority_updates
└── 不要修改 public API

state_evidence
└── [passed] python_validation / pytest / tests/test_auth.py

resource_hints
├── auth.py
└── tests/test_auth.py

recent_tool_transactions
├── edit auth.py
├── python_validation FAIL
├── edit auth.py
├── python_validation PASS
└── git diff
```

`Turn.root_task` 由 Turn 和 stable snapshot 提供，不在 digest 复制。最早的 read Observation 可由当前 workspace 重新获得；human clarification 保持为当前 Turn authority；第一次 FAIL 在 edit 时失效，随后 PASS 重新建立同一 validation key 的 current evidence。

# 3. 三个持久化对象

| 对象 | 角色 | 关键字段 |
|---|---|---|
| `conversation.jsonl` | raw Conversation authority | sequence、hash chain、完整 protocol item |
| `context_state.json` | Thread 级派生 Context State | `revision`、`covered_sequence`、digest、Turn snapshots |
| `TaskCheckpoint v4` | 当前 Run recovery | `context_revision` pointer、status、pending execution |

`covered_sequence` 是 journal compaction cursor；`revision` 是 `ThreadContextState` 的 CAS version；`TaskCheckpoint.context_revision` 只引用该 version。三者表达不同维度，不能互换。

新 Turn 的 stable snapshot 与 digest authority owner 在同一次 Context State CAS 中提交：

```text
Turn B snapshot persisted
+ digest.authority_turn_id = Turn B
+ digest.authority_updates = []
+ keep covered_sequence / source_hash / validation / breadcrumbs
```

因此磁盘 state、内存 state 与模型语义在 Turn boundary 后立即一致。

# 4. 一次 Rolling Compaction

入口是 `ModelStepPreparation.prepare_model_step()`：

```text
load ThreadContextState
→ verify TaskCheckpoint.context_revision
→ restore previous digest
→ read journal after covered_sequence
→ transaction-safe segmentation
→ rolling compact-prefix search
→ build delta digest
→ merge previous digest
→ CAS persist context_state.json
→ return final llm_messages
```

假设 previous digest 已覆盖 `1..850`，journal 尚有 `851..1000`。Repository 只加载 cursor 后的 items，并组成不可拆的 `S1, S2, S3 ...`：

```text
candidate 1 = previous digest + digest(S1)      + tail(S2..)
candidate 2 = previous digest + digest(S1..S2) + tail(S3..)
candidate 3 = previous digest + digest(S1..S3) + tail(S4..)
```

`PromptWindowManager.prepare()` 对每个 candidate 重新估算完整 request，包括 System Context、digest、recent tail、transient messages、Tool schemas 和 reserved output。第一个满足预算且确实缩小 prompt 的 candidate，就是最小可行 compact prefix。

实现用 rolling accumulator：每个 segment 只调用一次 `_build_digest()`，再由 `_merge_digest()` 累加，不重新解析已尝试的 prefix。Forced compaction 采用更保守的 target，但使用相同 legal transaction boundary。

CAS 成功后：

```text
covered_sequence = compacted prefix max sequence
conversation_history_digest = merged digest
revision = previous revision + 1
```

下一 Model Step 直接恢复 persisted digest，只加载新 delta。Journal delta 超过一页时，Runtime 分页 merge 并逐次 CAS 推进 cursor，追到 recent tail 后才发起模型调用。

# 5. Digest 状态模型

```text
ConversationHistoryDigest
├── authority_turn_id
├── authority_updates[]
├── resource_hints[]
├── state_evidence[]
├── recent_tool_transactions[]
├── covered_message_count
├── source_hash
└── token estimates
```

Digest 的时间边界是 `as of covered_sequence`。尚未 compact 的 recent-tail event 可能按时间顺序覆盖其中状态；模型同时看到 digest 与后续 event，因此 chronology 保持完整。

## 当前 Turn authority

`Turn.root_task` 是初始目标的唯一 owner，完整进入 `StableTurnContextSnapshot`。Digest 只接收当前 Turn 执行期的 human clarification 或 operator steer：

```text
role=user
AND human_authority=true
AND message.turn_id == current_turn_id
AND message.item_id != Turn.input_item_id
```

每条 authority 可做有界 excerpt，但整条不会被 first/last position rule 静默淘汰。超过 deterministic reserved capacity 时返回 `authority_context_overflow`。

## Validation 当前状态

只有带明确 typed contract 的 `python_validation` 进入 durable state：

```text
state_key = tool_name + check_type + validation_target
status    = passed | failed | blocked | unknown
```

状态来自 `Observation.validation_status`，同 key latest-value-wins，不同 target 独立。任何成功 workspace write 都直接 invalidates 已有 validation state；重新执行 `python_validation` 后才建立新 evidence。该 invalidation signal 只存在于一次 rolling merge 内，持久化和模型可见的只有最终 `state_evidence`。

Generic `run_command` 只进入 recent breadcrumbs。Tool visibility 由 `ToolRouter` 决定，history retention 由 Compaction contract 决定。

## Recent breadcrumbs 与 resource hints

`recent_tool_transactions` 保留 latest-N 工具意图与结果 excerpt，用于衔接最近执行，不承担 durable semantic memory。

`resource_hints` 从明确 Tool arguments 提取少量 path、validation target 或 keyword，按 recent unique 保留。它只帮助在当前 workspace 重新定位资源，不分析 Observation 内容。

具体 N、字符上限和 forced target 是 POC tuning parameters；ownership、transaction atomicity、latest-state-wins、workspace-write invalidation 与 fail-closed capacity 才是架构 contract。

# 6. New Turn 与 Same-Turn Resume

```text
Turn A completed
→ Turn B root task: 再补 regression test
→ persist Turn B StableTurnContextSnapshot
→ retarget digest authority to Turn B and clear Turn A updates
```

Turn A 的 raw items 继续留在 journal，但不再属于 Turn B 的 non-droppable authority。Turn B root task 由 `Turn.root_task` 和 stable snapshot 提供。

```text
same-Turn resume
→ restore StableTurnContextSnapshot
→ verify context_revision
→ restore digest from context_state.json
→ load journal only after covered_sequence
→ continue rolling compaction when needed
```

恢复对象是 durable snapshot、digest、cursor 和 execution state，不是 Python stack 或 Provider hidden state。

# 7. 能力边界

当前 deterministic contract 保证 raw Conversation 可审计、current Turn authority 不按位置丢失、typed validation state 有明确失效规则、Tool transactions 不被拆分。任意远古 Observation 中的语义事实召回不属于该 projection 的承诺；跨能力的规模扩展见 [生产化边界与扩展](生产化边界与扩展.md)。

# 8. 源码入口（Source Anchors）

- `agent_forge/runtime/domain/thread.py::ThreadContextState`：cursor、revision、digest 与 Turn snapshots。
- `agent_forge/context/domain/conversation_digest.py::ConversationHistoryDigest`：projection schema 与 retention invariants。
- `agent_forge/context/application/context_builder.py::build_stable_turn_context()`：完整 root task 与稳定前缀。
- `agent_forge/context/application/compaction.py::PromptWindowManager.prepare()`：segmentation、rolling search 与预算决策。
- `agent_forge/context/application/compaction.py::_build_digest()`：单个 raw delta 的确定性投影。
- `agent_forge/context/application/compaction.py::_merge_digest()`：previous + delta 的增量 merge。
- `agent_forge/runtime/application/model_step_preparation.py::ModelStepPreparation.prepare_model_step()`：分页追赶、CAS 与最终 messages。
- `agent_forge/runtime/adapters/thread_json.py::JsonConversationThreadRepository`：journal、Turn-boundary retarget 与 Context State persistence。
