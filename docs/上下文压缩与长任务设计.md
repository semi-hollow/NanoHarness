# 上下文压缩与长任务设计

> Compaction 只改变“下一次模型看见的历史投影”，不删除或改写 `ConversationThread` 中的原始对话。

# 1. 要解决的问题

长 Thread 会不断产生：

```text
user request / follow-up / operator steer
assistant text / ToolCall batch
Tool Observation
accepted final answer
```

全部原文直接发送给模型会超过 Provider context window。按固定消息数截断又可能丢掉任务约束，或拆开 assistant ToolCall 与对应 Observation。

因此系统把两件事分开：

```text
Durability: ConversationThread keeps every canonical item
Model input: PromptWindowManager projects a bounded view
```

# 2. 三层数据边界

| 数据 | Owner | 作用 |
|---|---|---|
| `conversation.jsonl` | `ConversationThreadRepository` | 完整 raw Conversation 与 hash chain |
| `ConversationHistoryDigest` | `ThreadContextState` | 已移出模型窗口的 deterministic derived projection |
| recent raw tail | `AgentRunSession.messages` | 当前模型仍需看到的最近交互 |

`trace.jsonl` 记录压缩原因、计数、token 估算和 source hash，但不是 raw Conversation store。

# 3. 模型窗口主链

```text
ModelStepPreparation.prepare_model_step()
    ↓
ThreadContextState
├── previous ConversationHistoryDigest
└── covered_sequence
    ↓
ConversationThreadRepository.list_items(after_sequence=...)
    ↓
bounded raw page
    ↓
PromptWindowManager.prepare()
    ├── within budget → previous digest + raw tail
    └── over budget   → merge smallest legal old prefix
    ↓
PromptWindowResult.llm_messages
    ↓
PreparedModelStep.llm_messages
    ↓
ModelPort.chat(...)
```

窗口估算同时包含：

- 当前 `ModelStepSystemContext`；
- previous digest；
- recent raw messages；
- transient Runtime control message；
- 独立发送的 Tool schemas；
- 预留的模型输出空间。

# 4. 增量滚动压缩（Incremental Rolling Compaction）

当前 V1 使用 deterministic rolling merge，不新增第二次 LLM 调用：

```text
previous digest
+
newly covered raw prefix
→ extract bounded task/tool/failure facts
→ merge digest
→ retain recent raw tail
```

它只读取 `covered_sequence` 之后的新 delta。旧 raw prefix 不重新加载，旧 digest 也不从头总结。

Digest 保留：

```text
initial_task
task_updates[]                 human-authority user inputs only
tool_transactions[]           intent + result
failed_tool_evidence[]
covered_message_count
source_hash chain
token estimates
```

`RuntimeCoordinationSignal` 即使投影为 `role=user`，也因为 `human_authority=false` 而不能进入 `task_updates`。

# 5. 合法压缩边界

`PromptWindowManager` 先把 history 分成不可拆的 segment：

```text
ordinary user/assistant message

assistant ToolCall batch
├── tool Observation 1
├── tool Observation 2
└── ...
```

每个 ToolCall batch 与全部 Tool Observations 必须一起进入 digest，或一起留在 raw tail。

`ask_human` 有一个额外边界：raw journal 为了授权 provenance，先保存 human-authority answer，再保存对应 Tool Observation；模型投影会在完整事务加载后规范化为 provider-valid 顺序：

```text
assistant ToolCall batch
→ all tool Observations
→ authoritative human answer
```

原始 sequence 不改写，只有 Provider projection 调整顺序。

# 6. 超过单页时如何追到最新消息

Repository 每次只返回有界 page，避免把无限 Thread 全量装进内存。

```text
load page after covered_sequence
→ stop at complete Tool transaction boundary
→ force deterministic merge
→ CAS save new covered_sequence and digest
→ load next page
→ repeat until latest raw tail is reachable
→ build exactly one final model request
```

中间 page 从不发给模型。否则最新用户 Turn 可能在第二页，而模型只看到旧的第一页。

# 7. Context State 的持久化

`ThreadContextState` 是独立 artifact boundary：

```text
schema_version
thread_id
revision
covered_sequence
conversation_history_digest
turn_snapshots[]
```

保存使用 compare-and-swap：调用方必须提交读取时的 `expected_revision`。另一个写入已经推进 revision 时，本次准备 fail closed，不做 last-write-wins。

两类计数不能混：

```text
covered_sequence
= canonical journal position

digest.covered_message_count
= cumulative audit count in the derived projection
```

`TaskCheckpoint.context_revision` 只指向当前 Context State；Checkpoint 不复制 digest。

# 8. Turn Snapshot 与 rolling digest 的区别

| 对象 | 冻结范围 | 何时变化 |
|---|---|---|
| `StableTurnContextSnapshot` | 当前 Turn 的 Prompt、Project Instructions、Skill、LTM recall、base tools | 新 Turn 才重建 |
| `ConversationHistoryDigest` | Thread 中逐渐变旧的 Conversation prefix | 需要压缩时增量推进 |
| dynamic context | 最新 turn focus、repository、Working Memory、Tool route | 每个 Model Step 重建 |

Snapshot 解决“同一 Turn resume 不换规则”；Digest 解决“跨 Turn 历史不撑爆模型窗口”。它们不是同一个对象。

# 9. Resume 如何继续

```text
Run A1 waits / pauses / crashes
    ↓
Harness.resume(A1 checkpoint)
    ↓
same Thread + same Turn + new Run A2
    ↓
restore StableTurnContextSnapshot
load ThreadContextState revision
load uncovered raw tail from conversation journal
resume pending ToolCall batch if present
```

Resume 不恢复 Python stack、Provider KV cache 或隐藏模型状态。它恢复的是显式 durable state，并重新进入确定性安全边界。

正常 follow-up 不走 Resume：它在同一个 Thread 下创建新 Turn，重新冻结新的 Turn Snapshot，同时继续复用此前 Conversation 与 rolling digest。

# 10. Provider overflow 恢复

若 Provider 明确返回 context overflow，Runtime 可以对同一 Model Step 强制生成更小窗口。只有新估算确实下降时才允许重试一次；否则直接停止，避免用相同请求重复计费。

强制压缩仍遵守：

- governing System Prompt 不裁剪；
- Tool transaction 不拆分；
- transient Runtime control 不进入 digest；
- CAS 成功后才使用新的 Context State；
- Trace 记录压缩前后估算，不记录完整 Prompt 正文。

# 11. 当前边界与生产方向

当前 deterministic digest 优先保证：

- 可预测；
- 低成本；
- 可恢复；
- 不增加 Provider timeout、retry、usage attribution 和 cancellation 链路。

它不是语义最强的总结器。生产增强方向是：

```text
deterministic boundary selection
→ one governed typed semantic-compaction call
→ Runtime validation
→ deterministic fallback
```

该 Hybrid LLM Compaction 当前未实现。
