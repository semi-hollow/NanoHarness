# 上下文压缩与长任务设计

> Prompt Window 把当前进程中的 Conversation History 治理成一次模型调用可接受的
> 消息视图。核心机制是 Previous Digest + Current-session Raw Delta，而不是每轮重扫
> 已经覆盖的历史。

# 1. 系统角色

模型请求同时占用窗口的内容是：

```text
turn_system_message
+ governed conversation
+ transient runtime-control message
+ tool_schemas
+ reserved output budget
```

随着 Turn 增加，历史会挤占输入窗口。直接按消息条数截断还可能拆开：

```text
assistant ToolCall
↔
tool Observation
```

`PromptWindowManager.prepare()` 的输入是当前 Session history、已有 digest、当前 Session
cursor 与 Tool schemas；输出是 `PromptWindowResult.llm_messages`、更新后的 digest、cursor
和预算证据。它的上游是 `TurnPreparation.prepare_turn()`，下游是
`ModelPort.chat(...)`。

# 2. 四个不能混淆的状态

| 状态 | 生命周期 | 真实含义 |
|---|---|---|
| `AgentRunSession.messages` | 当前进程中的一个 Run | 当前进程 raw Conversation；压缩不会删除它 |
| `ConversationHistoryDigest` | 可跨 Turn、可随 checkpoint 恢复 | 已覆盖旧交互的 durable derived projection |
| `AgentRunSession.compacted_message_cursor` | 当前 Session | `session.messages` 中已经进入 digest 的位置 |
| `ConversationHistoryDigest.covered_message_count` | 跨增量合并累计 | 审计计数，不是当前 Session list index |

另外：

```text
trace.jsonl
= durable execution evidence
≠ raw conversation store
```

因此系统没有声称 checkpoint 或 Trace 保存了跨进程完整对话。Resume 恢复的是有界
continuation projection，不是旧进程的 raw message list。

# 3. 一个 Turn 的窗口决策

```text
TurnPreparation.prepare_turn()
    ↓
PromptWindowRequest
├── conversation_history = list(session.messages)
├── previous_digest = session.conversation_history_digest
├── compacted_message_cursor = session.compacted_message_cursor
├── transient_messages
└── tool_schemas
    ↓
PromptWindowManager.prepare()
    ↓
current_session_delta
= conversation_history[compacted_message_cursor:]
```

第一次尚未压缩时，模型候选是：

```text
turn_system_message + current_session_delta + transient_messages
```

已经存在 digest 时，模型候选是：

```text
turn_system_message
+ previous_digest.render()
+ current_session_delta
+ transient_messages
```

在 soft limit 内直接复用该视图，不重建旧 digest。超过 soft limit 或 Provider 明确
报告 context overflow 时，才继续执行增量合并。

# 4. Rolling 增量合并（Snapshot + Delta）

```text
previous ConversationHistoryDigest
            +
current Session uncovered segments
            ↓
group into legal segments once
            ↓
for each next segment:
_build_digest([next_segment])
→ merge into rolling_delta_digest
→ estimate previous + rolling delta + recent tail
            ↓
first legal prefix restoring budget
            ↓
updated deterministic digest + recent raw tail
            ↓
PromptWindowResult.llm_messages
```

`_group_history_segments()` 只执行一次。候选从最小 legal prefix 开始；每扩大一个候选，
`_build_digest()` 只提取新加入的一个 segment，再合入 `rolling_delta_digest`，不会为
candidate 2 重新读取 candidate 1 已处理的 raw prefix。首次满足目标预算的候选立即提交，
因此保留尽可能多的 recent tail。

`_merge_digest()` 按结构化字段合并 task updates、tool transactions 和 failure evidence。
它不把上次 `digest.render()` 当作自然语言再总结，也不发起额外模型调用，因此不是
不可审计的 `summary(summary(...))`。

合并后：

```text
session.conversation_history_digest = updated digest
session.compacted_message_cursor += delta covered count
```

而：

```text
digest.covered_message_count
= previous cumulative count + delta covered count
```

两类计数分离，避免 resume 后用跨 Run 累计值索引新 Session 的 message list。来源 hash
也只证明 `previous_digest.source_hash + raw_delta.source_hash` 的确定性增量链，不冒充完整
raw Conversation hash。

# 5. 协议安全边界与 Recent Tail

`_group_history_segments()` 把普通消息作为独立 segment，并把一条 assistant ToolCall 与
紧随其后的全部 tool Message 绑定成不可拆分事务。候选搜索只在 segment 之间选择边界：

```text
old safe segments → delta digest
recent segments   → raw tail
```

不变量：

- `turn_system_message` 始终保留；
- assistant ToolCall 与对应 tool Message 同时进入 digest 或同时留在 raw tail；
- Tool schemas 参与完整请求估算；
- transient runtime-control Message 不写回 Session，也不进入 digest/cursor；
- recent tail 保持原协议结构；单条超大 Message 仍可使用现有 middle truncation，不能
  把它描述为 byte-exact raw persistence；
- 没有安全边界或没有实际缩小时，返回明确 reason，不伪称完成了新压缩。

# 6. Provider Overflow 恢复

正常阈值是 `PromptBudget.soft_input_limit`。Provider 明确返回 context overflow 时，
`AgentLoop` 再调用：

```text
TurnPreparation.prepare_turn(force_compaction=True)
```

强制路径仍只扫描 current raw delta，并使用更紧的 recent-message 截断与目标预算。只有
估算 token 确实下降时才允许重试模型；否则由 Runtime 明确停止，不能盲重放原请求。

# 7. Checkpoint 与 Resume

同一 Run 内：

```text
previous digest
+ session.messages[current_session_cursor:]
→ incremental merge
```

`TurnPreparation` 把更新后的 digest 写入 `TaskCheckpoint.conversation_history_digest`。
cursor 仍是进程内、当前 Session 的 list index，不单独持久化。

Resume / new continuation：

```text
TaskCheckpoint.conversation_history_digest
    ↓ ConversationHistoryDigest.from_dict()
NEW AgentRunSession.conversation_history_digest
NEW AgentRunSession.compacted_message_cursor = 0
    ↓
previous digest + new-session messages[0:]
```

`RunPreparation._load_resume_state()` 同时恢复 continuation summary 和 typed digest；它不
恢复旧 raw tail、旧 Python stack、Provider connection 或旧 cursor。

# 8. 与其他 Memory 的区别

```text
Prompt Window compaction
= 治理当前 Model request 的 Conversation 体积

WorkingMemory
= 当前 Run 的有界任务状态视图

Long-term Memory
= 用户明确授权、跨 Run 持久化并在新 Run 召回的记录

TaskCheckpoint summary
= continuation 的控制面摘要
```

四者生命周期和 authority 不同，不共享一个隐式 “memory summary”。

# 9. 设计边界

- Token 估算是调用前近似值；Provider usage 是调用后权威值；
- 当前 compaction 完全 deterministic，由预算或明确 overflow 触发，不声称进行自然语言
  重要性分类，也不会增加 Provider 调用；
- digest 是 durable derived continuation view，不是完整事实库；
- deadline、side-effect replay 和 no-progress detection 分别由 Runtime budget、
  Operation Ledger 与 `StepController` 管理，不属于 Prompt Window。

受治理的 typed LLM semantic compaction 是明确的生产化方向，但当前未实现；它的调用、
验证、成本和失败边界见 [生产化边界与扩展](生产化边界与扩展.md)。
