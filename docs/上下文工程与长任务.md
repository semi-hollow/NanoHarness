# 上下文工程与长任务

本文聚焦：

```text
Stable / Dynamic / Conversation Context 怎样分层？
长历史怎样 deterministic compaction？
Same-Turn Resume 怎样保持 Context contract？
```

> Context Engineering 的核心是把不同生命周期的信息分开：**一个 Turn 不该漂移的输入冻结；当前 workspace 事实每步重建；持续增长的 Conversation 通过 deterministic rolling compaction 进入有限模型窗口。**

# 1. 总体模型

```text
Turn-Stable Context
        +
Model-Step Dynamic Context
        +
Conversation Window
        +
Tool Schemas
        ↓
PreparedModelStep
        ↓
Model
```

三种生命周期：

```text
Stable
= 这个 Turn 按什么规则执行

Dynamic
= 此刻代码仓库是什么状态

Conversation
= 到目前为止发生了什么
```

# 2. Stable Turn Context

Fresh Turn：

```text
System Prompt
+ Turn.root_task
+ Project Instructions
+ selected Skills
+ LTM recall
+ base Tool schemas
        ↓
StableTurnContextSnapshot
```

Same-Turn Resume：

```text
load existing snapshot
→ validate
→ restore
```

不重新 discovery 稳定输入。

# 3. `stable_system_prefix`

`build_stable_turn_context()` 负责生成模型真正看到的稳定文字：

```text
mandatory
├── System Prompt
└── Turn.root_task

budgeted
├── Project Instructions
├── Skill cards
├── LTM recall
└── base Tool names
        ↓
stable_system_prefix
```

它是：

> **Turn-stable governing input 的 model-facing frozen projection。**

Snapshot 还保存 Tool schemas、Skill、Memory 与 evidence，因此 Same-Turn Resume 恢复的是完整稳定 contract，而不只是字符串。

# 4. Dynamic Model-Step Context

Workspace 会被 ToolCall 修改，所以动态事实不能冻结：

```text
turn_focus
+ current execution workspace
+ repository map
+ selected file previews
+ Working Memory
+ current Tool route
        ↓
ModelStepSystemContextBuildReport
```

每个 Model Step 重建。

最终：

```text
stable_system_prefix
+
dynamic system context
→ model_step_system_message
```

# 5. Raw Conversation 与 Prompt Window

`conversation.jsonl` 始终保存 lossless Conversation journal。

模型输入只读取：

```text
previous digest
+
items after covered_sequence
```

然后：

```text
PromptWindowManager.prepare()
→ compacted prefix projection
+ protocol-preserving recent tail
```

Compaction 不删除或改写 raw Conversation。

# 6. Rolling Compaction

Conversation 先切成合法事务段：

```text
S1 / S2 / S3 / ...
```

assistant ToolCall batch 与对应 Tool Observations 保持协议完整。

Runtime 从最小 prefix 开始：

```text
previous digest + compact(S1)       + tail(S2...)
previous digest + compact(S1..S2)   + tail(S3...)
previous digest + compact(S1..S3)   + tail(S4...)
```

第一个满足：

```text
完整 request ≤ target budget
AND
确实比原 request 更小
```

的 candidate 被采用。

这样优先保留尽可能多的近期协议结构与内容；超大消息仍可能做确定性截断。

# 7. Digest 是 Continuation State

`ConversationHistoryDigest` 不是自由文本总结，而是确定性 continuation projection。

核心字段：

```text
authority_updates
state_evidence
recent_tool_transactions
```

另有少量 bounded resource breadcrumbs，但它们不承担 authority 或 correctness state。

# 8. Human Authority

当前 Turn：

```text
Turn.root_task
= 初始目标 authority
```

Digest 只收后续真实人类约束：

```text
role=user
AND human_authority=true
AND current Turn
AND not root input
        ↓
authority_updates
```

新 Turn 开始时：

```text
Digest authority owner
→ retarget to new Turn

old authority_updates
→ cleared
```

跨 Turn 可延续的执行状态与当前 Turn 用户约束由此分开。

# 9. Validation Current State

只有 typed `python_validation` 建立 durable correctness state：

```text
state_key
= tool + check_type + validation_target

status
= passed / failed / blocked / unknown
```

同 key：

```text
latest value wins
```

任何成功 workspace write：

```text
previous validation state
→ invalidated
```

重新 validation 后才能建立新的 current state。

因此 Digest 保存：

> **当前代码仍然成立的 correctness evidence，而不是测试历史流水账。**

# 10. `ThreadContextState`

一个 Thread 只有一个：

```text
ThreadContextState
├── revision
├── covered_sequence
├── conversation_history_digest
└── turn_snapshots[]
```

含义：

```text
covered_sequence
= digest 已覆盖到哪个 Conversation sequence

revision
= 整份 ContextState 的 CAS version
```

# 11. Context Revision 一致性

运行中四个位置：

```text
ThreadContextState.revision
= durable authority

AgentRunSession.context_revision
= current Run live pointer

TaskCheckpoint.context_revision
= crash/resume durable pointer

RuntimeConfig.context_revision
= Run startup baseline
```

更新：

```text
persist new ContextState revision
→ update Session pointer
→ persist Checkpoint pointer
```

因此：

```text
ContextState=7 / Checkpoint=6
→ authority 已领先，可 Resume 时追平

Checkpoint=7 / ContextState=6
→ pointer 指向不存在 future state，拒绝
```

# 12. Long-Term Memory

新 Turn snapshot 构建时：

```text
root_task
→ visible Memory records
→ scope overlay
→ deterministic lexical relevance
→ budget
→ frozen LTM snapshot
```

Same-Turn Resume 不重新 recall。

Memory mutation 本身仍走 Run Governance；模型输出不能替代 human provenance。

# 13. 核心不变量

```text
1. Raw Conversation authority 与模型投影分离
2. Turn-stable 与 Model-Step dynamic input 分离
3. root_task 不复制进 Digest 成第二份 authority
4. Compaction 只推进 covered prefix
5. Human authority 不按 recency 静默淘汰
6. Workspace write 使旧 correctness evidence 失效
7. ContextState revision 是 durable Context authority version
```

# 14. 附录：长任务案例

```text
root_task:
修复 auth refresh bug

read auth.py
human steer:
不要修改 public API

validation → FAIL
write auth.py
validation → PASS
git_diff
```

Compaction 后：

```text
Stable Turn Context
└── root_task

Digest
├── authority_updates
│   └── 不要修改 public API
├── state_evidence
│   └── focused validation = PASS
└── recent breadcrumbs

Recent Tail
└── latest protocol-preserving messages; oversized content may be truncated
```

早期大段 read Observation 可以退出 Prompt；旧代码事实需要时重新读取当前 workspace。
