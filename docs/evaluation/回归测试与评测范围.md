# 回归测试与评测范围

本文维护四层不能混为一谈的证据：

1. **Canonical-50**：当前质量展示的唯一样本分数，使用预封存、确定性、按仓库分层的 50 题和 Pass@1。
2. **Golden-10**：已见的开发/回归集，用于选出 `showcase-quality-v1` 并诊断后续 Runtime 回归。
3. **Infrastructure Smoke-5**：五个真实 Case，只检查数据、checkout、工具、Patch、official evaluator 和 Evidence 链路。
4. **Runtime 契约回归**：针对审批、恢复、压缩、防重复和熔断等机制的 pytest 单元/集成测试。

只有 Canonical-50 完整分母上的 official verdict 可以形成当前样本质量结论。Golden-10 是已见开发集，
Infrastructure Smoke-5 是健康检查，Runtime 契约测试回答机制是否回归；三者都不是额外的 solved Case。

## 当前 Canonical Showcase

NanoHarness 使用 SWE-bench Verified `test` split 的 500 个公开 Case 作为冻结候选全集，数据 revision、
Arrow SHA-256 和行数都进入 manifest。Canonical-50 在看到结果前排除历史 Campaign、Golden-10 和
Infrastructure Smoke-5 已暴露的 Case，再使用固定种子和按仓库分层的确定性规则选取 50 题。
数据集身份和字段见
[SWE-bench Verified](https://huggingface.co/datasets/SWE-bench/SWE-bench_Verified)。

当前状态是 `showcase-quality-v1` 候选比较待执行、Canonical-50 待执行，所以还没有可发布的新分数。
不得用未完成分母、本地验证或 candidate Patch 数量填充结果。完整协议和实时状态见：

- [Canonical Showcase 状态](../../benchmarks/showcase/canonical-showcase-v1.json)
- [Golden-10 选型协议](../../benchmarks/showcase/quality-selection-protocol-v1.json)
- [Canonical-50 manifest](../../benchmarks/showcase/canonical-50-v1.json)

Canonical-50 完成后，公开表述仅为“确定性 50 题样本上 `X/50`”，不称为完整 SWE-bench
Verified 解决率，也不称为 Harness 相对模型的独立 uplift。

## Golden-10 开发/回归集

Golden-10 的 Case 已被历史开发观察过，当前只承担两个职责：用于两个质量候选的有界选型，以及后续 Runtime

它不进入 Canonical-50 分母，也不单独发布为质量分数。Case 清单见

### Infrastructure Case 查阅入口

```bash
# 查看集合目标、候选全集、选择方法和结论边界
forge bench cases

# 只查看 issue、base commit 和测试名称；不执行 Agent
forge bench case astropy__astropy-12907

# 仅在运行后复盘 official 验收实现或参考答案
forge bench case astropy__astropy-12907 --show-test-patch
forge bench case astropy__astropy-12907 --show-gold
```

默认输出不包含 official test Patch 或 gold Patch。这既方便检查每题怎样验收，也把数据泄漏边界
变成可执行契约，而不是口头约定。

### Infrastructure Smoke-5 运行

```bash
forge bench swebench --regression-set infrastructure-smoke-5 \
  --provider opencode-go --model deepseek-v4-pro \
  --temperature 0 --tool-routing task-aware --evaluate
```

每次运行生成 `results.json`、`scorecard.json`、`scorecard.md` 和 `report.md`。模型身份、资源配置、
dataset revision、Case 顺序、image identity 和 cache policy 必须进入证据。没有显式 per-case
resolved/unresolved report 时不报告 official resolved；Infrastructure Smoke-5 即使完成也只报链路健康状态。

## 为什么只接 SWE-bench 这一套外部评测

| 候选 | 当前决策 | 原因与后续触发条件 |
| --- | --- | --- |
| [SWE-bench Verified](https://www.swebench.com/) | 主外部基准 | 直接覆盖真实仓库 issue -> Patch -> official tests，与当前软件工程 AgentLoop 的产品边界一致。 |
| [Terminal-Bench 2.0](https://arxiv.org/abs/2601.11868) | 暂缓 | 更适合宽泛 terminal、多进程/多容器任务；等 Runtime 明确支持通用 shell execution 与相应隔离镜像后再接。 |
| [BFCL V4](https://gorilla.cs.berkeley.edu/leaderboard) | 不作为 Runtime 结果 | 主要衡量模型的函数/工具调用能力；NanoHarness 治理调用，但不把模型能力分数归功于 Harness。 |
| [τ-bench](https://arxiv.org/abs/2406.12045) | 暂不接 | 需要业务领域 API、policy 和 user simulator；适合业务 Agent，不是当前 repository-task 主线。 |
| 内部行为测试 | 必跑契约回归 | 验证 checkpoint、HITL、安全和 Evidence 语义；它不是外部 Agent 能力分数。 |
| 非 Coding 业务基准 | 当前不接 | 需要真实 domain API、policy、user simulator 和 executable oracle；不使用手写 Evidence scorecard 代替真实运行。 |

选择原则不是“Benchmark 越多越好”，而是每套评测都必须对应一个真实产品边界、一个可执行
oracle 和一个不会误导的 denominator。当前项目用 Verified 回答结果正确性，用行为测试回答
Runtime 契约，用 Trace/Scorecard 回答过程质量；三者不能互相替代。

## 从运行事实到改进决策

当前状态与冻结协议由 [Canonical Showcase](../../benchmarks/showcase/canonical-showcase-v1.json) 统一给出；早期失败和回滚案例
作为历史经验保留在[典型故障与系统调优记录](典型故障与系统调优记录.md)。`forge eval feedback` 保存人工复核结果；
`forge eval export-dataset` 默认不导出完整 Tool 参数、Observation、绝对路径或 Patch 正文。该流程不是自动改 Prompt
或 RL 训练平台。

## Runtime 契约回归（不是 SWE-bench Case）

下表每一行是一个机制验收场景。除第一行的 Infrastructure Case 外，其余主要由 pytest 单元/集成测试构造最小输入并

| 场景 | 保护的 Runtime 契约 | 主要测试证据 |
| --- | --- | --- |

| `validation-env-unavailable` / `context-miss-file-selection` | 环境故障与代码失败、检索缺失不能混淆。 | `tests/test_failure_taxonomy.py`、`tests/test_bench_failure_analysis.py` |
| `tool-governance-blocked-command` | 未授权命令不能越过 Tool/Command policy。 | `tests/test_command_policy.py`、`tests/test_agent_loop_policy.py` |
| `repeated-action-loop` / `tool-call-burst-bound` | 原地打转和单轮超额 ToolCall 必须受控。 | `tests/test_agent_loop_policy.py` |
| `manual-approval-pending` / `stale-approval-fingerprint` | 持久状态变更前停机；目标漂移后旧批准失效。 | `tests/test_human_approval.py` |
| `resume-state-continuation` | Checkpoint 恢复显式状态，不伪装成原地恢复 Python 栈或模型隐藏状态。 | `tests/test_task_resume.py`、`tests/test_resume_cli.py` |

## 指标与规则

每个 Case 分开保留 candidate Patch、local verified、official resolved、failure class、ToolCall、失败工具、
Context 选择/压缩、Token/成本/延迟、人工介入、持久操作去重和不支持声明数量。弱证据不会自动升格成强结论。

Runtime change 只有在至少一个预注册 Case 上改进 success、observability、failure localization、cost
或 safety boundary，同时没有隐藏其他 Case regression，才算有价值。比较 Runtime factor 时使用预注册 matched
run，并固定任务、model、dataset/split、预算、安全、Skill/Memory snapshot、执行环境和 official image。
任一身份或环境漂移都必须显式拒绝比较，不靠文案解释抹平。
