# 上下文工程

> Context Engineering 的目标不是“把能找到的文本都塞给模型”，而是在固定预算内，把当前 Model Step 真正需要的稳定规则、Conversation 历史、动态仓库事实和 Tool contract 组合成一份可审计输入。

# 1. 系统角色

Context 位于 Runtime 与 ModelPort 之间：

```text
ConversationThread + StableTurnContextSnapshot + repository state
    ↓
ModelStepPreparation.prepare_model_step()
    ↓
PreparedModelStep
    ↓
ModelPort.chat(...)
```

输入：当前 Turn、Thread Conversation、项目指令、Skill、Memory、仓库状态、Working Memory、Tool schemas 和预算。

输出：

- `PreparedModelStep.llm_messages`；
- `PreparedModelStep.tool_schemas`；
- 与本次调用一致的 `allowed_tool_names`；
- context/window/routing evidence。

它不调用模型、不执行工具，也不决定授权。

# 2. 当前 Model Step 的输入构造

```text
AgentRunSession
    ├── stable_system_prefix             frozen for this Turn
    ├── messages                         bounded Thread projection
    ├── working_memory                   derived run-local state
    ├── base_tool_schemas                frozen for this Turn
    └── turn_focus                       latest human-authority focus
            ↓
ModelStepPreparation.prepare_model_step()
    ├── ToolRouter.route()
    ├── Memory management candidates
    ├── RepositorySystemContextAssembler.build()
    │      └── ModelStepSystemContextBuildReport
    └── PromptWindowManager.prepare()
            ↓
PreparedModelStep
    ├── llm_messages
    ├── tool_schemas
    └── allowed_tool_names
            ↓
ModelPort.chat(...)
```

真实历史字段流：

```text
ConversationThread journal
↓
AgentRunSession.messages
↓
conversation_history = list(session.messages)
↓
PromptWindowRequest.conversation_history
↓
PromptWindowManager.prepare()
↓
PromptWindowResult.llm_messages
↓
PreparedModelStep.llm_messages
↓
ModelPort.chat(...)
```

# 3. Stable 与 Dynamic 必须分区

一次模型调用的 `ModelStepSystemContext` 由两部分组成：

```text
StableTurnContextSnapshot.stable_system_prefix
    +
ModelStepSystemContextBuildReport.dynamic context
    ↓
model_step_system_message
```

| 分区 | 内容 | 生命周期 |
|---|---|---|
| Stable | System Prompt、Project Instructions、Skill cards、LTM recall、base tools | 新 Turn 冻结；同 Turn resume 复用 |
| Dynamic | turn focus、repo map、file previews、retrieved docs、Working Memory、当前 Tool route | 每个 Model Step 重建 |

两块使用独立字符预算。Dynamic repository 内容不能挤掉 stable governing prompt。

# 4. Turn 稳定快照（StableTurnContextSnapshot）

`RunPreparation.prepare_run()` 在任何模型调用前执行：

```text
new Turn
→ PromptRegistry.get(profile)
→ resolve Project Instructions
→ select Skill
→ recall Long-Term Memory
→ snapshot base Tool schemas
→ build complete stable prefix
→ save StableTurnContextSnapshot with contract hash
```

Snapshot 同时保存 `runtime_contract`：

```text
context contract revision
model capabilities
system_prompt_profile
stable/dynamic context budgets
max_prompt_tokens
reserved_output_tokens
```

Resume 直接恢复 Snapshot。当前 Runtime contract 或 Tool registry 与 Snapshot 不一致时 fail closed。

同一 Turn 在等待 clarification 前已经冻结 Snapshot，因此等待期间修改 `AGENTS.md` 不会静默改变该 Turn；下一 Turn 才能看见新指令。

# 5. System Prompt 是 mandatory contract

`PromptRegistry` 提供三个明确 profile：

| profile | 角色 |
|---|---|
| `single_agent` | 独立完成完整仓库任务 |
| `fanout_worker` | 只执行 FanoutPlan 分配的子任务和 write scope |
| `fanout_finalizer` | 只读检查集成候选并返回结论 |

共同治理原则相同，但执行角色不同。未知 profile 直接失败，不能静默退回 Single Agent。

完整 System Prompt 是 stable partition 的 mandatory block。如果 stable budget 连完整 governing prompt 都放不下，构建失败；不会为了仓库正文而截断核心规则。

# 6. 项目指令（Project Instructions）

`resolve_instructions()` 按层级解析：

```text
global instruction files
→ workspace root instructions
→ nested instructions for instruction_target
→ explicit runtime override
```

解析结果及来源证据进入 `StableTurnContextSnapshot`。同一 Turn 后续 Model Step 不重复扫描文件。

指令只改变模型应遵循的项目规则，不扩大 Tool registry、write scope 或 Runtime authorization。

# 7. 动态仓库上下文（Dynamic Repository Context）

`RepositorySystemContextAssembler.build()` 每个 Model Step 读取当前执行 workspace：

```text
turn_focus
→ repository map
→ file ranking / retrieval
→ selected file previews
→ working-memory projection
→ dynamic budget allocation
→ ModelStepSystemContextBuildReport
```

Repo Map 只描述结构；正文按当前文件动态读取。结构缓存的 invalidation 边界是：

- `replace_text` / `write_file` 改正文：结构不变，不强制重建 map；
- `create_file`：结构变化，invalidate；
- `run_command`：可能 create/delete/rename，保守 invalidate；
- 下一次 build 比较 structure revision 后决定是否重建。

文件检索和排名可以随 `turn_focus` 改变，但 stable Snapshot 与安全策略不变。

# 8. 会话历史（Conversation History）

Raw history 的权威 Owner 是 `ConversationThread`：

```text
conversation.jsonl
├── human user input
├── assistant content / ToolCall batch
├── Tool Observations
├── operator steer / human answer
├── runtime coordination evidence
└── accepted final answer
```

`AgentRunSession.messages` 只是从 journal 重建的有界投影。Message 仍携带 `origin/human_authority`，避免把 provider role 当成授权事实。

历史过长时，`PromptWindowManager` 使用 `ConversationHistoryDigest + recent raw tail`。压缩只更新 `ThreadContextState`，不改写 raw journal。

# 9. 工作记忆（Working Memory）

Working Memory 保存当前 Run 中对下一步有帮助的派生状态，例如恢复建议和局部工作线索。它不是：

- raw Conversation；
- Tool Observation 镜像；
- Long-Term Memory；
- durable source of truth。

Tool Observation 已由 Thread journal 和 Trace 保存；再复制进 Working Memory 只会制造重复输入。

# 10. Long-Term Memory 的两个视图

新 Turn 创建时冻结 task-aware recall：

```text
visible USER + PROJECT memories
→ exact-key PROJECT override
→ task relevance
→ PROJECT tie-break
→ recency
→ character budget
→ StableTurnContextSnapshot.long_term_memory_snapshot
```

该 snapshot 服务当前任务 reasoning，同一 Turn 内不会因为新写入 Memory 而变化。

`remember_memory` 使用另一条管理视图：

```text
latest human-authority turn_focus
→ bounded visible Memory Management Candidates
→ memory_id / scope / key / compact content
→ attach only to remember_memory schema
```

它不作为普通 reasoning evidence。`CREATE` 不带 `target_memory_id`；`UPDATE/NOOP` 必须指向当前候选中的 `memory_id` 且 scope 一致。

写入还必须携带 `source_quote`，Runtime 在当前 Turn 的 human-authority user item 中做精确原文匹配。历史 Turn、runtime coordination 和模型文本都不能授权新的 Memory write。

# 11. Tool schemas 与 Authorization 是两层

`ToolRouter.route()` 根据 `turn_focus`、step、Skill 和 execution phase 选择本次模型可见 schemas，同时返回 `allowed_tool_names`。

```text
Tool schema visibility      = what the model may propose now
Tool authorization         = whether this concrete call may execute
```

模型提出的调用仍必须经过：

```text
route recheck
→ tool guardrail
→ provenance / Operation Ledger
→ Hook / Approval
→ ToolGateway
```

Steer 可以改变下一步的检索和路由，但不能扩大 Snapshot 中冻结的 base Tool capabilities，也不能绕过安全门。

# 12. Transient Runtime 输入

接近 step budget 时，Runtime 可以追加临时控制 Message，要求模型收口。该 Message：

- 只进入当前 `PromptWindowRequest.transient_messages`；
- 不写入 `ConversationThread`；
- 不进入 rolling digest；
- 不携带 human authority。

Runtime coordination 与 transient control 不同：coordination 是 Worker 间可审计事实，会持久化到私有 Worker Thread，但始终标记 `human_authority=false`。

# 13. 证据（Evidence）

Trace 只记录输入构造证据，不复制敏感 Prompt 正文：

- Snapshot contract hash 与是否 reused；
- Project Instructions 来源；
- selected Skill 与 LTM memory IDs；
- selected files、dropped sections 和字符预算；
- Tool routing 原因和 visible names；
- compaction count、source hash 与 token estimate；
- ModelCapabilities。
