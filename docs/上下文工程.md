# 上下文工程

[← 架构导览](./架构导览.md#context)

<a id="overview"></a>

> NanoHarness 将一次 Run 的 live state 派生为单次模型调用需要的 Runtime Context、History View 与 Tool Schemas。本文先给出完整主链；后半部分仅用于字段、时序和边界的按需下钻。

## 1. 总览 / Overview

```text
AgentRunSession(messages | observations | working_memory | evidence)
        ↓
TurnPreparation(ContextAssembler | ContextWindowManager | ToolRouter)
        ↓
PreparedTurn(messages_for_llm | schemas)
        ↓
ModelPort.chat(...)
        ↓
AgentResponse(reasoning_content | tool_calls | content)
```

### 核心关系

```text
AgentRunSession = 一次 Run 的 live mutable source
PreparedTurn    = 当前 Turn 冻结后的 Model Input snapshot

Model Input
= Current Runtime Context
+ Conversation History View
+ Tool Schemas

Runtime Context = 当前世界，每 Turn 重建
Raw History     = 已发生的 chronological protocol facts
WorkingMemory   = bounded run-local read model / scratchpad
Compaction      = old raw history → protocol segments → semantic SessionDigest

stable prefix first + dynamic tail later
→ 提高 Provider Prefix Cache 复用的可能性，不保证命中
```

# 详细设计 / Detailed Design

> 以下部分不是主链的重复展开，而是对上方节点的字段、时序和设计边界做按需说明。

<a id="session"></a>

## 2. 运行会话 / AgentRunSession

[↑ 返回 Overview](#overview)

```text
AgentRunSession
├── task
├── messages[]
├── observations[]
├── working_memory
├── evidence
├── lifecycle
├── controller
├── active_skills
├── estimated_cost_usd
├── status
├── stop_output
└── stop_reason
```

`AgentRunSession` 是一次 Run 的内存态容器，不是 Model Input，也不是 Trace。

`session.messages` 是按时间 append 的原始协议历史：

```text
user
assistant(tool_calls + optional reasoning)
tool(observation)
assistant(tool_calls + optional reasoning)
tool(observation)
user(operator steer)
...
```

它是单一 chronological list，不按 role 分桶。

<a id="model-io"></a>

## 3. 模型输入输出 / Model I/O

[↑ 返回 Overview](#overview)

物理接口：

```python
llm.chat(
    prepared_turn.messages_for_llm,
    prepared_turn.schemas,
)
```

逻辑来源：

```text
① Current Runtime Context
② Conversation History View
③ Tool Schemas
```

Provider 边界看到：

```text
messages_for_llm
├── Current Runtime Context      role=system
├── Optional SessionDigest       role=system
└── Recent Raw History
    ├── user
    ├── assistant
    └── tool

schemas
└── 当前 Turn 的 Tool Schemas
```

`session.task` 会参与文件选择、检索和上下文策略，但不应理解成 Runtime Context 中又渲染一份独立 `task:` section；初始任务已经作为 `role=user` History 进入模型协议。

<a id="message-response"></a>

## 4. 消息与模型响应 / Message / AgentResponse

[↑ 返回 Overview](#overview)

```text
Message
├── role
├── content
├── name
├── tool_call_id
├── tool_calls
└── reasoning_content
```

`tool_call_id` 是 assistant ToolCall 与 tool Observation 的事务关联 ID。

```text
AgentResponse
├── content
├── reasoning_content
├── tool_calls[]
├── error
├── usage
├── response_id
├── observed_model
└── normalization
```

控制流：

```text
tool_calls != []
→ Runtime 执行 Tool
→ Observation
→ 下一 Turn

tool_calls == []
→ response.content
→ FinalAnswerBuilder
→ STOP candidate
```

两 Turn 的 Tool-interleaved reasoning：

```text
Turn N
LLM
├ reasoning_content = 为什么做
└ tool_calls         = 做什么
        ↓
Runtime execute
        ↓
Observation          = 实际发生了什么
        ↓
History append
assistant(reasoning + ToolCall)
tool(Observation)
        ↓
Turn N+1
```

`reasoning_content` 是 Provider reasoning payload 的短期连续性状态，不是 Final Answer、授权状态或 durable memory。旧 reasoning 在 compaction 时不进入 SessionDigest。

<a id="runtime-context"></a>

## 5. 当前运行时上下文 / Current Runtime Context

[↑ 返回 Overview](#overview)

Current Runtime Context 每 Turn 重建，并整体渲染为当前 `role=system` Message。

核心 section：

```text
system_prompt
permission_summary
attention_sink
available_tools
active_skill_cards
project_instructions
long_term_memory
selected_file_previews
retrieved_docs
working_memory_summary
working_memory_items
repo_map
selected_files
```

`context_state` 是 render 阶段生成的 section，不应当作 `ContextBuildReport` 的独立 dataclass 字段理解。

过去 Turn 的 Runtime Context 不 append 到 `session.messages`。

<a id="stable-prefix"></a>

## 6. 稳定前缀与提示缓存 / Stable Prefix / Prompt Cache

[↑ 返回 Overview](#overview)

先区分两层 `system`：

```text
协议层：
Message(role="system", content=<rendered runtime context>)

rendered content 内：
system:
  <system_prompt>
```

内层 `system` 只是 Runtime Context 的一个 section，不是第二条 system Message。

`system_prompt` 承担：

```text
Agent identity
+ base runtime behavior
+ evidence-oriented execution policy
```

### 相对稳定区 / 相对动态区

```text
相对稳定区
────────────────────────
system_prompt
permission_summary
attention_sink
available_tools
active_skill_cards
project_instructions
long_term_memory

相对动态区
────────────────────────
selected_file_previews
retrieved_docs
working_memory_summary
working_memory_items
repo_map
selected_files
render-time context state
Conversation History
```

“相对稳定”不等于每 Turn 完全不变；`system_prompt` 通常是最稳定的 prefix anchor。

NanoHarness 不实现 Provider 内部 Prompt Cache；Runtime 负责：

```text
1. stable-prefix-friendly input layout
2. Provider-reported cache usage observability
```

单 Run usage 可观测：

```text
cache_hit_tokens
cache_miss_tokens
cache_hit_rate
reasoning_tokens
```

Campaign 聚合是否完整，以实验 reporting 层为准；不能把 layout 说成 guaranteed cache hit。

<a id="working-memory"></a>

## 7. 工作记忆 / WorkingMemory

[↑ 返回 Overview](#overview)

```text
WorkingMemory
├── items
├── observations
├── summaries
├── store
├── long_term_records
└── n
```

```text
items
→ 当前 Run 最近显式 facts

observations
→ 最近 bounded Tool observations

summaries
→ 被 recent observation window 挤出的旧 Observation 摘要
→ continuation / resume summary

store
→ run-local explicit Key-Value scratch state
→ 不是 lifecycle state
→ 这里的 KV 不是 Transformer KV Cache

long_term_records
→ Run 启动时冻结的 LTM snapshot
```

WorkingMemory 是给 ContextAssembler 使用的 bounded run-local materialized view：

```text
Runtime / Persistence
        ↓ projection
WorkingMemory
        ↓
ContextAssembler
```

它避免 ContextAssembler 直接依赖完整 AgentRunSession、Checkpoint、LTM Repository、全部 observations 和 persistence internals。

它在 `RunPreparation.create_session()` 创建 `AgentRunSession` 时随 Run 建立；`items`、
`observations`、`summaries` 与 `store` 可在本 Run 内更新，`long_term_records` 则是 Run-start
召回快照。新 Tool Observation 超过 recent window 后，最旧项会变成只保留 Tool、成败和短 excerpt
的确定性 compact note；渲染时 recent observations、summary notes 与整体字符数还会再次 bounded。
整条 `Current Working Set → recent observations → compact notes → bounded render` 链不调用 LLM。

<a id="observation"></a>

## 8. 工具观察 / Observation

[↑ 返回 Overview](#overview)

工具真实执行结果统一表示为 `Observation`：

```text
Observation
├── tool_name
├── success
├── execution_succeeded
└── content
```

同一个 Tool Result 会投影到不同消费模型：

```text
Tool execution
      ↓
 Observation
      │
 ┌────┼───────────────────────┐
 ▼    ▼                       ▼
session.observations   WorkingMemory   Message(role=tool)
typed runtime facts    recent view     Provider protocol
```

同一事实还会进入 Trace / Evidence，供审计、Workbench 和最终引用使用；这些是面向不同消费者的
projection，不是四套相互竞争的真相源。

其中 `Message(role=tool)` 只在本轮执行后仍允许继续时追加；若执行结果提交后立即命中停止预算，
`session.observations`、WorkingMemory、Trace 与 Checkpoint 已保留事实，但不会再构造下一轮模型消息。

<a id="evidence-ledger"></a>

## 9. 最终答案证据 / EvidenceLedger

[↑ 返回 Overview](#overview)

`session.evidence` 不属于 Model Input 主链，它是面向 Final Answer 的 evidence read model。

```text
Observation
↓
EvidenceLedger.add_observation()
↓
筛选值得引用的事实
↓
EvidenceItem
```

FinalAnswerBuilder 取最终 citations，与模型 `response.content` 组合成带 provenance 的最终输出。

没有 EvidenceLedger，Agent 仍可读写代码、运行测试和生成 patch；损失的是 Final Answer 的 grounding、provenance 与可审计引用，而不是 Tool execution correctness。

<a id="compaction"></a>

## 10. 会话压缩 / Compaction / SessionDigest

[↑ 返回 Overview](#overview)

核心：

> **Protocol Segmentation + Semantic Projection**

### 协议分段 / Protocol Segmentation

`assistant ToolCall + matching tool Observation(s)` 作为不可拆协议事务。

### 语义投影 / Semantic Projection

旧 Segment 被投影为结构化 `SessionDigest`：

```text
SessionDigest
├── task
├── covered_message_count
├── source_hash
├── task_updates[]
├── tool_transactions[]
├── failed_tool_evidence[]
├── estimated_tokens_before
├── estimated_tokens_after
└── created_at
```

`ToolTransactionDigest`：

```text
tool_name
arguments_summary
success
observation_excerpt
```

### 确定性重算 / Deterministic Recalculation

每个 Turn 都从 Raw History 重新计算当前 Digest：

```text
Raw History
→ current deterministic Digest
```

而不是：

```text
Digest A → Digest B → Digest C
```

这样避免 recursive summary-of-summary 的累计语义漂移，同时保持确定性、可复现和可审计。

两套压缩需要严格区分：Conversation History 经 protocol-aware compaction 进入 `SessionDigest`，
Current Working Set 经 recent window 与 compact notes 进入 `WorkingMemory`。前者压
`session.messages` 并保留 Tool 协议事务；后者压当前事实集合；两者都不额外调用 LLM。

<a id="recovery"></a>

## 11. 恢复与续跑 / Recovery / Continuation

[↑ 返回 Overview](#overview)

```text
Old Run
↓
TaskCheckpoint
↓
summarize_checkpoint()
↓
deterministic resume_summary
↓
NEW AgentRunSession
↓
WorkingMemory.seed_session()
↓
Current Runtime Context
```

当前不是 Full State Rehydration：

```text
Full Rehydration
= serialized state → 原完整 live object

NanoHarness continuation
= Durable State → Continuation Context
```

状态边界：

```text
AgentRunSession
= live mutable state

TaskCheckpoint
= durable latest-state projection

Trace / trace.jsonl
= append-only event history

Approval / Operation Ledger / Human Input / LTM
= independent durable stores
```

Persistence 不是把 AgentRunSession 原样序列化。
