# 上下文工程

> Context Engineering 在固定预算内，把稳定治理规则、Conversation history、当前仓库事实和 Tool contracts 组合成一次可审计的 Model Step 输入。

# 1. 系统角色

```text
ConversationThread + StableTurnContextSnapshot + current repository state
→ ModelStepPreparation.prepare_model_step()
→ PreparedModelStep
→ ModelPort.chat(...)
```

输入包括当前 Turn、Conversation、Project Instructions、Skill、Memory、repository state、Working Memory、Tool schemas 和预算。输出是 `PreparedModelStep.llm_messages`、本步 tool schemas、`allowed_tool_names` 与构造证据。Context 层负责输入治理；模型调用、Tool execution 和授权由相邻 Runtime owner 完成。

# 2. 当前 Model Step 的输入构造

```text
AgentRunSession
├── stable_system_prefix              frozen for this Turn
├── messages                          bounded Thread projection
├── working_memory                    run-local derived state
├── base_tool_schemas                 frozen capability set
└── turn_focus                        latest human-authority focus
        ↓
ModelStepPreparation.prepare_model_step()
├── ToolRouter.route()
├── current Memory management candidates
├── RepositorySystemContextAssembler.build()
│   └── ModelStepSystemContextBuildReport
└── PromptWindowManager.prepare()
        ↓
PreparedModelStep
├── llm_messages
├── tool_schemas
└── allowed_tool_names
        ↓
ModelPort.chat(...)
```

Conversation 字段流可直接对应源码：

```text
ConversationThread journal
→ AgentRunSession.messages
→ conversation_history = list(session.messages)
→ PromptWindowRequest.conversation_history
→ PromptWindowManager.prepare()
→ PromptWindowResult.llm_messages
→ PreparedModelStep.llm_messages
→ ModelPort.chat(...)
```

# 3. 稳定区与动态区

```text
StableTurnContextSnapshot.stable_system_prefix
+ ModelStepSystemContextBuildReport dynamic context
→ model_step_system_message
```

| 分区 | 内容 | 生命周期 |
|---|---|---|
| Stable | System Prompt、Project Instructions、Skill cards、LTM recall、base tools | 新 Turn 冻结；same-Turn resume 复用 |
| Dynamic | turn focus、repository map、file previews、Working Memory、当前 Tool route | 每个 Model Step 重建 |

两个分区使用独立预算。Stable governing contract 先完整建立，Dynamic repository context 在自己的预算内选择和裁剪。

# 4. Turn 稳定快照（StableTurnContextSnapshot）

`RunPreparation.prepare_run()` 在首次模型调用前完成：

```text
Turn.root_task
→ PromptRegistry.get(profile)
→ resolve Project Instructions
→ select Skill
→ recall Long-Term Memory
→ snapshot base Tool schemas
→ build stable system prefix
→ persist StableTurnContextSnapshot + contract_hash
```

Snapshot 的 `runtime_contract` 记录 context revision、model capabilities、Prompt profile、预算和 Tool registry compatibility。Resume 校验 contract 后恢复快照；不兼容则在调用模型前停止。等待 clarification 期间 Snapshot 仍保持不变，新项目指令在下一 Turn 生效。

三个 Prompt profile 对应三种执行角色：

| Profile | Runtime role |
|---|---|
| `single_agent` | 独立处理完整任务 |
| `fanout_worker` | 执行一个受 write scope 约束的 SubagentTask |
| `fanout_finalizer` | 只读验证 Multi-Agent 集成结果 |

# 5. 动态仓库上下文

`RepositorySystemContextAssembler.build()` 每个 Model Step 读取当前 execution workspace：

```text
turn_focus
→ repository map
→ file ranking / retrieval
→ selected file previews
→ working-memory projection
→ dynamic budget allocation
→ ModelStepSystemContextBuildReport
```

Repository map 表达结构，selected previews 提供正文。文件创建或可能改变目录结构的 command 会使结构 revision 失效；普通正文编辑仍会在下一次 build 读取最新文件内容。动态 Context 始终描述当前 workspace，而非旧 Tool Observation 的副本。

# 6. Conversation、Working Memory 与长期记忆

三种信息按生命周期分开：

| 信息 | Owner | 进入模型的方式 |
|---|---|---|
| 原始对话（Raw Conversation） | `conversation.jsonl` | Digest + protocol-preserving recent tail |
| Run 内派生状态 | `WorkingMemory` | dynamic system context projection |
| 跨 Turn 显式记忆 | `LongTermMemoryService` | new-Turn frozen recall snapshot |

`WorkingMemory` 保存当前 Run 的局部线索和恢复建议；Tool Observation 已由 Conversation journal 与 Trace 保存。长历史压缩由 [上下文压缩与长任务设计](上下文压缩与长任务设计.md) 负责。

Long-Term Memory 有两个有界视图：

```text
new Turn task
→ task-aware recall
→ StableTurnContextSnapshot.long_term_memory_snapshot

latest human-authority turn focus
→ current management candidates
→ remember_memory schema only
```

Recall 服务 reasoning；management candidates 约束显式 `CREATE / UPDATE / NOOP`。Memory write 必须携带 `source_quote`，Runtime 在当前 Turn 的 human-authority 原文中精确验证 provenance。

# 7. Tool visibility 与执行授权

`ToolRouter.route()` 依据 turn focus、step、Skill 和 phase 生成本步 `schemas + allowed_tool_names`：

```text
Tool visibility       model may propose this tool now
Tool authorization    this concrete call may execute
```

模型提出 ToolCall 后，执行链仍会重新校验 route、guardrail、provenance、Operation Ledger、Hook 与 Approval。稳定快照约束 capability 上限，动态 route 只在该上限内收窄。

# 8. Transient 输入、证据与恢复

接近 step budget 时，Runtime 可追加 transient control message。它只进入当前 `PromptWindowRequest.transient_messages`，不写 Thread journal，也不进入 digest 或 human authority。

Trace 记录构造证据而非完整 Prompt 正文：snapshot contract hash、instruction sources、selected Skill/memory IDs、selected files、预算、Tool route、compaction metrics 和 model capabilities。

Same-Turn resume 恢复稳定 Snapshot 和 Thread Context State，然后按当前 workspace 重建 Dynamic Context。这样稳定规则保持一致，代码事实仍反映恢复时的实际 workspace。

# 9. 源码入口（Source Anchors）

- `agent_forge/runtime/application/run_preparation.py::RunPreparation.prepare_run()`：冻结或恢复 Turn 稳定输入。
- `agent_forge/runtime/application/model_step_preparation.py::ModelStepPreparation.prepare_model_step()`：Context、history 与 tools 汇合。
- `agent_forge/runtime/adapters/context_assembler.py::RepositorySystemContextAssembler`：动态仓库 Context。
- `agent_forge/context/application/context_builder.py::build_stable_turn_context()`：稳定前缀与 root task。
- `agent_forge/context/application/context_builder.py::ModelStepSystemContextBuildReport`：动态 Context 构造报告。
- `agent_forge/context/application/instructions.py::resolve_instructions()`：分层 Project Instructions。
- `agent_forge/context/application/compaction.py::PromptWindowManager.prepare()`：Conversation window 治理。
- `agent_forge/memory/application/service.py::LongTermMemoryService`：recall 与显式 mutation。
