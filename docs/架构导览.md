# 架构导览

本文聚焦：

```text
系统整体怎么分层？
Single / Governance / Context / Multi 怎样关联？
哪些 design invariants 最值得优先评审？
```

> NanoHarness 是一个由确定性 Runtime 治理模型提案的 Coding Agent Harness。整体设计沿四条主线展开：**一个 Agent 怎样运行、模型动作怎样被治理、长任务怎样管理 Context、多个 Worker 怎样形成可信结果。**

# 1. 系统全景

```text
用户目标
  ↓
Single-Agent Runtime
  ↓
模型提出下一步
  ↓
Runtime Governance
  ↓
Durable Facts
  ↓
下一次模型决策
```

复杂任务在这条主链上扩展：

```text
长任务
→ Context lifecycle + rolling compaction

并行任务
→ Planner + isolated Workers + trusted integration
```

四个总原则：

```text
Model proposes
Runtime governs
Durable facts drive recovery
Trusted state has explicit ownership
```

# 2. 运行身份

```text
ConversationThread
└── Turn
    ├── Run 1
    └── Run 2 (resume)
        └── Model Step 1..N
```

| 层级 | 含义 |
|---|---|
| `ConversationThread` | 持续用户会话 |
| `Turn` | 一个顶层用户目标 |
| `Run` | 该 Turn 的一次 execution attempt |
| `Model Step` | Run 内一次模型调用 |

```text
Follow-up = same Thread + new Turn + new Run
Resume    = same Thread + same Turn + new Run
```

# 3. Single-Agent

主生命周期：

```text
建立可恢复执行
→ 准备当前任务
→ 模型决策
→ 处理动作或结果
→ 继续 / 等待 / 完成
```

对应 Runtime：

```text
Harness
→ RunPreparation
→ AgentLoop
→ ToolExecutionPipeline / FinalAnswerBuilder
→ RunLifecycle
```

详见 [单 Agent 运行链路](单Agent运行链路.md)。

# 4. Run Governance

模型 ToolCall 不能直接越过真实副作用边界：

```text
ToolCall
→ capability / protocol
→ operation identity
→ replay / idempotency
→ authorization
→ real execution
→ durable Observation
```

关键区分：

```text
Tool visibility
≠
Tool authorization
≠
Side effect execution
```

详见 [运行治理与副作用](运行治理与副作用.md)。

# 5. Context Engineering

一次模型调用汇合三类生命周期：

```text
Turn-stable governing input
+
Model-Step dynamic workspace facts
+
Thread Conversation history
```

长任务：

```text
raw Conversation journal
→ deterministic digest for covered prefix
+ recent protocol tail
→ bounded Prompt Window
```

详见 [上下文工程与长任务](上下文工程与长任务.md)。

# 6. Multi-Agent

Multi-Agent 不增加第二套 Agent reasoning runtime，而是增加编排与 trust layer：

```text
Planner proposal
→ Runtime validation
→ isolated Workers
→ candidates
→ Coordinator integration gate
→ trusted workspace
```

关键区分：

```text
execution concurrency
≠
trusted integration ordering
```

详见 [多 Agent 编排](多Agent编排.md)。

# 7. Durable Control Plane

不同事实由不同 durable owner 保存：

```text
Conversation
Context state
Run checkpoint
Approval / Human input
Operation state
Trace / artifacts
```

恢复不是读一个万能 checkpoint，而是重新组合这些 authoritative facts。

详见 [持久化与恢复](持久化与恢复.md)。

# 8. 最有区分度的设计

| 设计 | 核心价值 |
|---|---|
| Stable Turn Context + rolling compaction | 长任务保持稳定治理输入和有限模型窗口 |
| Durable assistant batch + pending cursor | 中断后精确续跑原 Tool batch |
| Operation Ledger + target fingerprint | 副作用跨 crash 不盲目重放 |
| Human authority 与 Provider role 分离 | transport 角色不能提升为授权事实 |
| Candidate 与 trusted integration 分离 | Worker 并发不直接污染可信 workspace |
| LIVE freshness gate | 提前协作但不降低最终一致性 |

# 9. 专题关系

```text
单 Agent 运行链路
        ↓
运行治理与副作用
        ↓
上下文工程与长任务

Multi-Agent
= 在 canonical Single-Agent Runtime 外增加 planning / isolation / trust

持久化与恢复
= 为以上能力提供 durable control plane
```
