# 架构导览

> 本文是 NanoHarness 的统一架构入口。按系统责任、运行主链和核心数据结构组织，不按 package 罗列类。

<a id="system"></a>

# 1. 系统定位

```text
NanoHarness = capability-oriented Hexagonal Architecture
apps/                      ← CLI / Console / Showcase / Workbench / MCP 入站应用
agent_forge/harness.py     ← standalone Single-Agent public facade
agent_forge/<capability>/  ← Runtime / Context / Memory / Tool / Multi-Agent 等 Core

能力包内部：application 编排用例，domain 保存业务语义，ports 定义边界，adapters 实现外部 IO。
`agent_forge` Core 不依赖 `apps`；`agent_forge.__main__` 只是 executable bootstrap 例外。
```

核心原则：

```text
Model proposes
Runtime decides
Execution produces facts
Evidence verifies results
```

```text
AgentRunSession
├── task
├── messages[]                     ← Conversation History
├── observations[]
├── working_memory
├── active_skills[]
├── lifecycle
├── controller
├── evidence
└── status / budget / stop state
        │
        ▼
TurnPreparation.prepare_turn()
        │
        ▼
PreparedTurn
├── turn_system_message
├── llm_messages
├── tool_schemas
├── allowed_tool_names
├── conversation_history_digest
└── prompt metrics
```

关键区别：

```text
AgentRunSession
= 跨 Turn 存活的运行状态

TaskCheckpoint
= durable latest-state snapshot

ConversationHistoryDigest
= 旧 Conversation History 的结构化压缩投影
```

# 4. LLM 输入的三块来源

```text
                         PreparedTurn
                              │
             ┌────────────────┴────────────────┐
             │                                 │
             ▼                                 ▼
 PreparedTurn.llm_messages        PreparedTurn.tool_schemas
             │
       ┌─────┴───────────┐
       │                 │
       ▼                 ▼
turn_system_message  PromptWindowRequest.conversation_history
        │                 │
        ▼                 ├── raw history
TurnSystemContextBuildReport.render()
                          └── digest + recent raw tail
```

Current Turn System Context 每 Turn 重建：

```text
Runtime / Policy
├── system prompt
├── permission summary
├── project instructions
└── attention sink

Knowledge
├── repo map
├── selected files / previews
├── retrieved docs
└── long-term memory

Capability
├── active Skill cards
└── available tool names

Working State
├── WorkingMemory summary
└── WorkingMemory items
```

它 render 成：

```text
turn_system_message
= Message(role="system", ...)
```

Conversation History 则独立来自：

```text
AgentRunSession.messages
```

# 5. 提示窗口（Prompt Window）

Provider 最终需要的是一个有序 Message 序列，因此 Runtime 会构造：

```python
full_llm_messages = [
    request.turn_system_message,
    *request.conversation_history,
]
```

其中：

```text
turn_system_message
= 1 个 system Message

conversation_history
= list[Message]
```

`*` 是 Python list unpacking：

```text
[S, *[M1, M2, M3]]
=
[S, M1, M2, M3]
```

Message 个数不是“注意力权重”。

真正需要治理的是：

```text
token volume
role
position
relevance
long-context degradation
```

当前系统通过：

```text
system role
+ bounded Current Turn System Context
+ attention_sink
+ Prompt soft limit
+ protocol-aware history compaction
+ recent raw tail
```

降低历史噪声。

当前明确边界：

> History 即使尚未达到 soft limit，也仍可能产生语义干扰；当前 compaction 主要由 token budget 触发，而不是由“语义注意力污染”触发。这属于后续 Context Engineering 的可演进项。

# 6. 运行治理（Runtime Governance）

```text
LLM ToolCall
    │
    ▼
ToolExecutionPipeline._execute_call()
    │
    ▼
OperationTracker.build_operation_intent()
    │
    ▼
OperationTracker.resolve_existing_operation()
    │
    ▼
ToolAuthorizationGate.authorize()
    │
    ├── before_tool lifecycle hooks
    │     ├── ExecutionEnvironmentHook
    │     ├── PermissionHook
    │     └── custom hooks
    │
    ├── DENY
    ├── ASK → ApprovalRepository
    └── ALLOW
    │
    ▼
Ledger: executing                  ← side-effect only
    │
    ▼
ToolExecutionPipeline._run_tool()
    │
    ▼
ToolGateway.execute()
    │
    ▼
raw Observation
    │
    ▼
HookManager.after_tool()
    │
    └── SecretRedactionHook
    │
    ▼
final Observation
    │
    ├── Operation Ledger result
    ├── WorkingMemory
    ├── Evidence
    ├── Trace
    ├── session.observations
    ├── Checkpoint
    └── if Run continues → AgentRunSession.messages(role=tool)
```

详细见 `运行治理与工具执行.md`。

# 7. 持久化控制面（Durable Control Plane）

```text
TaskCheckpoint
├── identity
├── status / current_step
├── last_tool / last_observation
├── stop / resume fields
├── message / observation counts
└── conversation_history_digest
```

除此之外：

```text
ApprovalRepository
= 是否授权

OperationLedgerRepository
= 副作用执行状态

HumanInputRepository
= 用户问题与回答

Trace
= append-only happened-before evidence
```

Resume：

```text
Old TaskCheckpoint
↓
summarize_checkpoint
↓
resume_summary
↓
NEW AgentRunSession
↓
WorkingMemory.seed_session(...)
```

Resume 是 continuation，不是旧 Python Session resurrection。

# 8. 多 Agent 编排（Multi-Agent）

稳定版本：

```text
Typed FanoutPlan
↓
Dependency / Conflict-free Scheduling
↓
Independent Worker AgentLoops
↓
Isolated Git Worktrees
↓
Candidate Diff
↓
Conflict Gates
↓
Stable Integration
↓
Read-only Finalizer
```

V1 capability branch（CURRENT）：

```text
Natural Task
↓
Planner
↓
Single / Fanout Gate
↓
Validated FanoutPlan
↓
Workers + WorkerHandoff
↓
Integration
↓
Bounded Recovery / Replan
↓
Criteria-aware Finalizer
```

V2 定量评测和自动语义冲突解决仍是 FUTURE / NOT IMPLEMENTED。

核心原则不变：

```text
LLM proposes
Runtime validates
```

# 9. 评测（Evaluation）

```text
Fixed Case Cohort
↓
Agent Runtime
↓
Candidate Patch + Trace
↓
Official Evaluator
↓
Resolved / Unresolved / Empty Patch / Infra
↓
Scorecard / Failure Review
```

固定实验只证明对应 cohort、模型和 runtime revision 上的结果，不把相关性冒充单一 feature 的因果收益。
