# 架构导览

> NanoHarness 的统一架构入口：先建立 Ownership 与执行主链，再按能力文档下钻。

---

<a id="system"></a>

# 1. 系统定位

```text
Inbound applications
├── apps/                           CLI / Console / Showcase / Workbench / MCP
└── agent_forge/harness.py          Single-Agent embedded API
              │
              ▼
agent_forge/<capability>/
├── application                     用例编排与控制流
├── domain                          业务规则与状态语义
├── ports                           对外依赖边界
└── adapters                        文件、Git、Provider 等 IO 实现
```

`Harness.run` 是 Single-Agent composition root；各能力包不依赖展示应用。核心治理原则：

```text
Model proposes
Runtime decides
Execution produces facts
Evidence verifies results
```

# 2. 总体主链

```text
RunRequest
    ↓
Harness.run()
    ├── ExecutionEnvironment
    ├── RuntimeDependencies
    └── AgentLoop
            ↓
      AgentLoop.run()
            ↓
      RunPreparation.prepare_run()
            ↓
      bounded Turn loop
            ↓
      TurnPreparation.prepare_turn()
            ↓
      PreparedTurn
            ↓
      ModelPort.chat(...)
            ↓
      AgentResponse
       ├── final text → FinalAnswerBuilder
       └── ToolCall   → ToolExecutionPipeline → Observation → next Turn
            ↓
      RunLifecycle.finalize_run()
            ↓
      TaskCheckpoint + Trace + Run artifacts
```

`Harness` 负责外部输入、Adapter 装配和产物收口；`AgentLoop` 只拥有 Runtime
控制流；阶段规则分别由对应 Application Owner 执行。

# 3. Agent 运行数据模型

```text
AgentRunSession                         PreparedTurn
├── task                               ├── turn_system_message
├── messages[]                         ├── llm_messages
├── observations[]        ─Turn─→      ├── tool_schemas
├── working_memory                     ├── allowed_tool_names
├── conversation_history_digest        ├── prompt metrics
├── compacted_message_cursor           └── conversation_history_digest?
├── memory_management_candidates
├── lifecycle
├── controller
└── status / budget

TaskCheckpoint
└── durable latest-state snapshot
```

- `AgentRunSession`：跨 Turn 的内存状态；
- `PreparedTurn`：一次模型调用的冻结输入；
- `TaskCheckpoint`：恢复控制面使用的最新状态；
- `ConversationHistoryDigest`：被压缩旧历史的结构化投影。

详细数据关系见 [Agent 运行数据结构与模型输入](Agent运行数据结构与模型输入.md)。

<a id="context"></a>

# 4. LLM 输入的三块来源

```text
PreparedTurn
├── turn_system_message
│     └── TurnSystemContextBuildReport.render()
├── llm_messages
│     └── system message + governed conversation history
└── tool_schemas
      └── ToolRouter selected contracts
```

System Context 提供当前稳定事实，Conversation History 提供交互顺序，Tool Schemas
提供结构化能力契约。三者分别治理，最终在 `PreparedTurn` 汇合。

# 5. 提示窗口（Prompt Window）

```text
AgentRunSession.messages
    + previous ConversationHistoryDigest
    + current-session cursor
    ↓
PromptWindowRequest
    ↓
PromptWindowManager.prepare()
    ├── within soft limit → reused digest + uncovered raw delta
    └── over limit        → merged digest + recent raw tail
    ↓
PromptWindowResult.llm_messages
    ↓
PreparedTurn.llm_messages
```

压缩不修改 live Session 的原始会话历史，也不能拆开 assistant ToolCall 与对应 tool
Observation；Trace 只记录窗口度量、来源 hash 与压缩事实。详细机制见
[上下文压缩与长任务设计](上下文压缩与长任务设计.md)。

Long-Term Memory 的 task-aware Recall Snapshot 在 `RunPreparation` 生成并进入
`WorkingMemory`；按最新 human message 查询的 bounded Management Candidates 只附加到
当前 Turn 的 `remember_memory` schema。同一次 AgentLoop 模型调用提出一条或多条
CREATE/UPDATE/NOOP，Runtime 验证 human-authority user quote 与 target ID 后才持久化；
完整边界见 [上下文工程](上下文工程.md)。

<a id="governance"></a>

# 6. 运行治理（Runtime Governance）

```text
Model ToolCall
    ↓
ToolExecutionPipeline._execute_call()
    ↓
OperationTracker.build_operation_intent()
    ↓
ToolAuthorizationGate.authorize()
    ├── DENY
    ├── ASK → ApprovalRepository
    └── ALLOW
    ↓
Operation Ledger: executing            side-effect only
    ↓
ToolExecutionPipeline._run_tool()
    ↓
ToolGateway.execute()
    ↓
HookManager.after_tool()
    ↓
redacted Observation
    ├── Ledger / WorkingMemory / Evidence / Trace / Checkpoint
    └── Run continues → AgentRunSession.messages(role=tool)
```

授权、工具 dispatch 和副作用状态是三个独立边界。完整链路见
[运行治理与工具执行](运行治理与工具执行.md)。

<a id="durability"></a>

# 7. 持久化控制面（Durable Control Plane）

```text
Authoritative mutable state
├── TaskCheckpoint
├── Approval
├── HumanInput
├── Operation Ledger
└── Long-term Memory

Audit evidence
└── trace.jsonl

Derived presentation
├── trace.json / usage.json
└── reports / Workbench
```

Resume 从旧 checkpoint 构造新的 continuation run，不复活 Python stack、Provider
连接或完整 Conversation。详细契约见 [运行产物与持久化契约](运行产物与持久化契约.md)。

# 8. 多 Agent 编排（Multi-Agent）

Planning 与 execution 是 Application composition 的相邻阶段，不是
`FanoutCoordinator.run()` 内部隐式调用 Planner：

```text
Natural-language Task
    ↓
AdaptivePlanner.decide()
    ↓
PlanningDecision → validated FanoutPlan
    ↓
Application composition
    ↓
build_live_fanout()
    ↓
FanoutCoordinator.run()
    ↓
current effective plan generation
    ├── HARD-only          → _run_batch()
    └── has LIVE routes    → _run_live_plan()
    ↓
isolated Worker AgentLoops
    ↓
Candidate Integration
    ├── success
    └── bounded retry / merge recovery / remaining-plan replan
                                      ↓
                              next FanoutPlan generation
                                      ↓
                         scheduling strategy selected again
    ↓
read-only Finalizer
```

每个 effective plan generation 独立选择 scheduling strategy；remaining-plan
replan 后可以在 HARD 与 LIVE 之间切换。完整设计见 [多 Agent 编排](多Agent编排.md)。

<a id="evaluation"></a>

# 9. 评测（Evaluation）

```text
Fixed Case Cohort
    ↓
RunSwebench.run_benchmark()
    ↓
LocalCaseExecutor.run() → build_agent_loop() → AgentLoop.run()
    ↓
Candidate Patch + canonical Trace
    ↓
Official Evaluator
    ↓
resolved / unresolved / empty patch / infrastructure failure
    ↓
Scorecard and failure projection
```

Candidate diff、local validation 和 official result 是不同事实。评测层读取证据并投影，
不把本地检查自动提升为 official pass。

## 源码入口（Source Anchors）

- `agent_forge/harness.py::Harness.run()`：Single-Agent public composition root。
- `agent_forge/runtime/application/agent_loop.py::AgentLoop.run()`：Run 的唯一主循环。
- `agent_forge/runtime/wiring.py::build_agent_loop_from_request()`：Runtime 依赖装配。
- `agent_forge/runtime/application/turn_preparation.py::TurnPreparation.prepare_turn()`：模型输入汇合点。
- `agent_forge/runtime/application/tool_execution.py::ToolExecutionPipeline._execute_call()`：工具治理主链。
- `agent_forge/runtime/application/run_lifecycle.py::RunLifecycle.finalize_run()`：终态持久化 Owner。
- `agent_forge/multi_agent/application/fanout.py::FanoutCoordinator.run()`：Multi-Agent 执行与集成。
- `agent_forge/bench/application/swebench.py::RunSwebench.run_benchmark()`：单 Case benchmark 入口。
