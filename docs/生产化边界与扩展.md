# 生产化边界与扩展

> 本文只记录当前 contract 的适用边界与规模扩大后的自然扩展点。各能力的真实执行链仍以对应 canonical 文档为准。

# 1. 当前系统边界

NanoHarness 面向单机、本地 workspace、可审计 Coding Agent 场景。当前设计优先保证：

```text
explicit authority
+ deterministic runtime decisions
+ crash-recoverable local state
+ traceable execution evidence
+ bounded model context
```

规模扩展时，首先保留 ownership 与 trust boundary，再替换存储、检索或调度实现。

| 能力 | 当前 Contract | 扩展触发点 | 可替换方向 |
|---|---|---|---|
| Context Compaction | deterministic rolling prefix + typed continuation projection | 任意旧 Observation 的语义召回成为产品要求 | governed semantic compaction / retrieval |
| Long-Term Memory | explicit human-authorized records + bounded lexical recall | 大规模记录、跨租户、复杂去重 | indexed/hybrid retrieval + transactional repository |
| Multi-Agent | local threads、worktrees、bounded concurrency、strict frontier | 跨进程/跨机器 worker | durable queue、lease、remote workspace、distributed scheduler |
| Persistence | local atomic JSON/JSONL + file lock + canonical v4 | 多节点、跨 region、online migration | transactional event/state store + schema registry |
| Runtime Governance | local policy、Approval、Operation Ledger | remote tools、多租户、组织策略 | identity/policy service、secret manager、central audit |

# 2. Context 与 Memory

当前 compaction 始终由 Runtime 选择 legal boundary，并把旧 prefix 投影为 current-Turn authority、typed validation state、resource hints 和 recent breadcrumbs。Raw Conversation 独立留在 journal。

当前 Long-Term Memory 只写入带 human provenance 的显式 record；new-Turn recall 与 mutation candidates 是两个独立 bounded views。记录量较小时，线性 lexical retrieval 保持行为可解释。

当产品开始要求 long-horizon arbitrary semantic recall 时，扩展层仍应遵守：

```text
raw authority remains immutable
→ semantic process proposes derived state
→ Runtime validates typed result
→ projection quality is evaluated
```

Semantic process 需要独立的 timeout、cost、cancellation、trace 和 fallback contract，不能取得 `covered_sequence` 或 human authority 的写权限。

# 3. Multi-Agent 执行规模

当前 Fanout 由单进程 scheduler、local worktree、private Worker Thread、HARD/LIVE semantics 和 strict trusted integration prefix 组成。它完整表达 planning、isolation、candidate governance 与 recovery 的控制闭环。

跨机器后，需要把以下本地事实提升为 durable distributed contracts：

```text
Attempt lease and identity
Worker delivery and retry
LIVE version replay
remote workspace snapshot
integration serialization
resource quota and cancellation
```

Worker 仍只产生 candidate，Coordinator 仍拥有 integration；执行位置改变不改变 trust ownership。

# 4. Persistence 与 Runtime Governance

本地文件协议提供 process-crash recovery：atomic mutable state、append-only Conversation/Trace、per-Thread lock、Tool batch cursor 和 Operation Ledger。它不声称能事务回滚已经发生的任意外部副作用。

多节点持久化需要 transactional state、lease/fencing、retention、encryption、tenant isolation 和 online schema migration。Historical Evidence 的 presentation compatibility 继续与 Runtime recovery loader 隔离。

Remote Tool governance 需要稳定 principal identity、集中 policy、secret boundary、Approval channel 与 audit export。模型 proposal、concrete-call authorization 和 external effect 仍应保持三个阶段。

# 5. 扩展时保持的不变量

1. Raw authority、derived projection 与 execution evidence 分离。
2. 模型提议，Runtime 持有状态转换与副作用 authority。
3. Worker candidate 与 trusted integration 分离。
4. Resume 只恢复能够由 durable evidence 证明的状态。
5. 新实现先定义 failure/cancellation/replay contract，再进入主链。
