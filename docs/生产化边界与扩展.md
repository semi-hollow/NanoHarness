# 生产化边界与扩展

本文是跨能力的生产规模边界 Owner。各能力当前控制流仍由对应 canonical 文档解释；
这里不重复源码主链，也不形成版本 Roadmap，只区分：当前实现为何足够、规模扩大后先会
遇到什么边界、可能沿什么方向演进。

# 1. 上下文压缩（Context Compression）

## 当前设计（Current Design）

```text
Previous ConversationHistoryDigest
+ ConversationThread Uncovered Raw Delta
→ deterministic legal segmentation
→ rolling prefix accumulator
→ smallest legal prefix restoring budget
→ deterministic digest merge + recent protocol tail
```

Runtime 独占 boundary、cursor、covered count、source hash、Tool transaction 和预算决定。
当前路径不调用额外模型；Provider overflow 时也只有确实缩小窗口才重试原任务调用。

## 为什么当前足够（Why It Is Sufficient Here）

- 行为可预测，同一输入产生相同 digest；
- 每个新 segment 在一次 scan 中只提取一次；
- 没有额外 Provider 成本、延迟和失败面；
- raw Conversation 独立保存在 Thread journal，checkpoint 只指向有界 derived state；
- ToolCall 与 Observation 始终在同一 legal segment。

## 生产规模边界（Production-scale Boundary）

确定性 excerpt 不能可靠理解长篇 assistant prose 中的设计决定。字符到 token 的估算也
不是 Provider tokenizer。单条超大 Message 仍可能需要截断。更长任务还需要评估 digest
是否遗漏约束、积累漂移或造成后续决策退化。

## 可能方向（Possible Production Direction）

```text
deterministic boundary selection
→ one governed LLM semantic-compaction call
→ typed semantic state
→ Runtime validation
→ deterministic fallback
```

该调用必须使用独立 purpose，进入 Hook、Trace、usage、cost、cancel 和 deadline 归因；
模型不能改写 Runtime authority 字段。还需要 summary quality evaluation、drift monitoring
和 provider-cost policy。以上均未在当前版本实现。

# 2. 长期记忆（Long-Term Memory）

## 当前设计（Current Design）

```text
explicit human evidence
→ remember_memory CREATE / UPDATE / NOOP
→ Runtime provenance and target validation
→ JSON repository

new Turn task → frozen bounded Recall Snapshot
latest human-authority message → current Model Step bounded Management Candidates
```

`memory_id` 是 record identity；`key` 只承担 topic 与 PROJECT-over-USER override label。
Recall 服务 reasoning，Management Candidates 只服务显式 mutation，两者不混用。

## 为什么当前足够（Why It Is Sufficient Here）

- Memory 数量小，linear lexical scan 直接且可解释；
- storage size 不直接决定 model-context size；
- 写入必须绑定当前 Thread 的 human-authority 原文；
- 多条显式写入可以顺序审计，`ask_human` 仍保留独占屏障；
- 没有隐藏 consolidator model call，也没有 Model-visible delete。

## 生产规模边界（Production-scale Boundary）

当记录达到 `10^5 / 10^6` 量级，JSON 全量扫描、跨进程并发、去重质量、租户隔离、配额、
PII 和查询观测都会成为独立问题。当前 lexical overlap 也不能覆盖所有语义相关性。

`TTL / LRU / decay` 不应机械作用于用户明确授权的 durable memory。生产系统应先区分：

```text
explicit durable memory
≠ derived / episodic memory
```

再分别制定 retention、archival 和 deletion policy。

## 可能方向（Possible Production Direction）

- inverted index、BM25、vector 或 hybrid retrieval；
- large-scale deduplication 与 consolidation quality evaluation；
- 存储配额（quota）、保留与归档（retention / archival）、隐私与 PII 策略；
- transactional repository、concurrency control 和 audit export。

这些方向当前均未实现。

# 3. 多智能体（Multi-Agent）

## 当前设计（Current Design）

当前实现使用有界 local thread、独立 worktree、typed plan、HARD/LIVE dependency、
worker-specific coordination mailbox、candidate diff 和确定性 integration gates。

## 为什么当前足够（Why It Is Sufficient Here）

它能验证 Planner、Worker 隔离、LIVE evidence delivery、版本检查、失败恢复和最终集成的
控制闭环，同时避免引入分布式一致性协议。

## 生产规模边界（Production-scale Boundary）

跨进程或跨机器后，内存 mailbox、local lock 和本机 worktree 不再提供足够的 durable
delivery、lease、replay、身份认证和资源调度保证。

## 可能方向（Possible Production Direction）

可考虑分布式执行、持久化 LIVE replay、远程 workspace、worker lease、更大规模的
scheduler 和跨节点 observability。当前未实现这些能力。

# 4. 持久化与检查点（Persistence / Checkpoint）

## 当前设计（Current Design）

```text
ConversationThread
├── thread.json                     Turn/Run navigation
├── conversation.jsonl              complete authoritative items
├── context_state.json              digest + StableTurnContextSnapshot
└── terminal_intents/<turn_id>.json terminal commit intent

TaskCheckpoint v4
├── thread_id / turn_id / run_id
├── context_revision
├── execution workspace
└── pending assistant item / call cursor
```

Thread metadata、context state、Approval、Ledger 等 mutable state 使用 same-directory
atomic replace 与 fsync；Conversation 与 Trace 使用各自 append-only JSONL。Trace 最终
JSON、usage 和 report 是 derived projection。Checkpoint 不保存 Python stack、Provider
connection、root task 或完整 raw conversation。

普通 follow-up 创建 same Thread / new Turn / new Run；Resume 创建 same Thread / same Turn /
new Run。`StableTurnContextSnapshot` 在同一 Turn 的 Resume 中复用，Runtime contract 不兼容时
fail closed。完整 assistant ToolCall batch 在执行前写入 Thread，checkpoint cursor 只在
唯一 Tool Observation durable 后推进。

Turn 终态按 terminal intent → terminal checkpoint → Turn/current ThreadRun commit 提交；本地
loader 会在 intent 与 canonical checkpoint 完全一致时幂等补完最后一步。

## 为什么当前足够（Why It Is Sufficient Here）

本地多进程通过 per-Thread file lock 串行化 authoritative append；hash chain、稳定 item
identity 与幂等 append 给出明确 crash boundary。副作用 `executing` 但无最终结果时仍按
unknown outcome fail closed，而不是宣称文件协议能够事务回滚外部系统。

## 生产规模边界（Production-scale Boundary）

远程恢复、跨节点 lease、跨 region durability、数据保留和 online migration 需要超出
本地文件系统的事务与并发保证。当前 Worker/Finalizer private Thread 也是本地 durable
conversation，不构成分布式 mailbox replay。

## 可能方向（Possible Production Direction）

可考虑事务 event store、远程对象存储、租约、保留策略、schema registry 和 online
migration。当前未实现这些能力。生产 Runtime 只接受 current canonical schema；历史
Evidence 的 read-only presentation compatibility 不能进入恢复路径。

# 5. 工具与运行时治理（Tool / Runtime Governance）

## 当前设计（Current Design）

当前 Runtime 在本地完成 Tool routing、guardrail、authorization、Approval、Operation
Ledger、Observation、Hook 和 budget control。模型提出动作，Runtime 决定是否可执行并
保存结果事实。

## 为什么当前足够（Why It Is Sufficient Here）

单用户、本地 workspace 下，权限、side effect、unknown outcome 和 replay 边界均有唯一
Owner，能够直接从 Trace 与持久状态验证。

## 生产规模边界（Production-scale Boundary）

多租户、远程 Tool、组织级策略和集中审计会要求独立身份、密钥、policy distribution、
tenant isolation 与合规导出。

## 可能方向（Possible Production Direction）

可考虑策略服务、密钥管理、租户身份、远程审批、审计导出和统一 telemetry backend。
当前未实现这些能力。

- `agent_forge/runtime/domain/thread.py::ConversationThread`：Thread/Turn/Run、raw items 与稳定 context contract。
- `agent_forge/runtime/application/model_step_preparation.py::ModelStepPreparation.prepare_model_step()`：当前 Model Step Context、Candidates 与 Tool schema 汇合。

- `agent_forge/runtime/application/run_lifecycle.py::RunLifecycle`：accepted final、v4 checkpoint 与 Turn 终态。
- `agent_forge/runtime/application/tool_execution.py::ToolExecutionPipeline.resume_pending_calls()`：原 assistant batch 恢复边界。
