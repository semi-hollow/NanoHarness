# 运行产物与持久化契约

> 持久化层把四类事实分开：用户对话真相、Runtime 恢复状态、append-only 执行证据、只读展示投影。恢复只消费前两类。

# 1. 四类持久化角色

```text
Authoritative Conversation
├── thread.json
└── conversation.jsonl

Authoritative Mutable State
├── context_state.json
├── terminal_intents/<turn_id>.json
├── TaskCheckpoint v4
├── HumanInput / Approval
├── Operation Ledger
└── Long-Term Memory

Append-only Execution Evidence
└── trace.jsonl

Derived Presentation
├── trace.json / usage.json / reports
└── Workbench views
```

| 类型 | 回答的问题 | Runtime 用途 |
|---|---|---|
| Conversation | 用户、模型与 Tool 的权威协议顺序 | 重建对话与未闭合 batch |
| Mutable State | 当前 Run/Turn/operation 停在哪里 | crash resume 与 CAS update |
| Trace | 实际发生过哪些执行事件 | audit、debug、metrics projection |
| Presentation | 怎样便于人读取 | 展示，不驱动恢复 |

# 2. Thread 控制面

```text
.agent_forge/internal/state/threads/<thread_id>/
├── thread.json
├── conversation.jsonl
├── context_state.json
├── terminal_intents/<turn_id>.json
└── .lock
```

`thread.json` 保存 Thread identity、workspace、active Turn、Turn/Run navigation、journal tail metadata。`conversation.jsonl` 每行保存一个带 sequence、hash chain、Turn/Run identity、protocol payload 与 `origin/human_authority` 的 `ConversationItem`。

`context_state.json` 保存：

```text
ThreadContextState
├── revision                         CAS version
├── covered_sequence                 compaction cursor
├── conversation_history_digest      derived prefix projection
└── turn_snapshots[]                 stable input per Turn
```

创建新 Turn 时，stable snapshot 与 digest authority retarget 在同一次 Context State CAS 中提交。

# 3. Run 恢复状态（TaskCheckpoint v4）

```text
TaskCheckpoint
├── identity       run_id / thread_id / turn_id / agent_name
├── workspace      requested + actual execution workspace / mode
├── lifecycle      status / current_step / stop state
├── context        context_revision
└── pending_execution
    ├── assistant_item_id
    ├── next_tool_call_index
    ├── pending_operation_key
    └── pending_operation_fingerprint
```

Turn 的 canonical root task 位于 `Turn`；Conversation 正文位于 journal；digest 位于 Thread Context State。Checkpoint 保存执行恢复所需的 identity、status 和 pointer。

```text
Normal follow-up
= same Thread + new Turn + new Run

Resume
= same Thread + same Turn + new Run
```

`Harness.resume(checkpoint_path)` 校验 canonical v4、active Turn、workspace、execution worktree、Context State revision 与 stable snapshot contract，然后优先继续 pending execution。

# 4. Tool Batch 的 Durable Sequence

```text
1. append complete assistant batch
2. persist pending cursor
3. recheck route / guardrail / authorization / operation fingerprint
4. execute or produce deterministic non-execution result
5. append exactly one Tool Observation
6. advance cursor
```

这个顺序让恢复端同时拥有模型完整提案和精确执行位置。等待 Approval、Human Input 或 Pause 时，cursor 保持在当前调用；terminal stop 会为未闭合调用产生明确 non-execution Observation。

| Crash point | Durable recovery action |
|---|---|
| assistant 已写，cursor 未写 | 从同 Turn 唯一 unfinished batch 重建 cursor |
| Observation 已写，cursor 未推进 | 只推进 cursor |
| side effect ledger 为 `executing`，result 缺失 | outcome unknown，fail closed |
| accepted final 已写，terminal checkpoint 缺失 | 复用原 final 并完成 terminal checkpoint |
| terminal checkpoint 已写，Turn 仍 active | 校验 terminal intent 后幂等提交 Turn/ThreadRun |

# 5. Operation Ledger 与终态提交

Checkpoint 表达 Run 的执行位置；Operation Ledger 表达一个副作用是否已经发生：

```text
planned / pending
→ approved
→ executing
→ executed | failed
```

Operation key 绑定 normalized intent，fingerprint 绑定执行前目标状态。相同 durable invocation 可以 replay result；新的调用保持独立；`executing` 且结果未知时不自动重做。

Turn 终态按三步提交：

```text
terminal intent
→ terminal TaskCheckpoint
→ Turn + current ThreadRun commit
```

Thread loader 只在 intent 与 checkpoint 的 thread/turn/run identity 和 terminal status 一致时补完最后一步。

# 6. Run Artifact 与 Trace

```text
.agent_forge/runs/.../<run>/
├── run_request.json
├── run_manifest.json
├── trace.jsonl
├── trace.json
├── usage.json
├── task_state/<run_id>.json
├── candidate_changes.diff
├── stop_output.txt
├── final_answer.txt
└── execution_environment.json
```

每个 Run 都有 stop output；只有 accepted `COMPLETED` 写入 `final_answer`。`candidate_changes.diff` 表示该 Run 的候选 workspace change，不属于 Conversation 或 recovery state。

`trace.jsonl` 是每 Run 单 writer 的 append-only evidence。Reader 可以忽略并报告最后一条 crash-truncated line，中间损坏则停止。`trace.json`、usage 和 reports 从 JSONL 投影。

Trace 不保存完整 model prompt 或 raw Conversation。它保存 `model_step_started` 等事件及输入构造、Tool execution、checkpoint 与 stop evidence。

# 7. 写入与 Schema 边界

Authoritative mutable JSON 采用同目录 temp、flush、fsync、replace、parent fsync。Conversation append 在 per-Thread file lock 内验证 hash chain，写入一行并 fsync，再原子更新 metadata。

Journal metadata 落后时，可以从带完整 turn-start metadata 的权威 item 修复；metadata 超前、hash 中间损坏或 terminal identity 冲突时 fail closed。最后一条 crash-truncated journal line 可截除并报告。

Production Runtime loader 只接受当前 canonical v4。冻结的旧 Evidence 保持只读；展示旧 schema 时使用独立 `read-only presentation compatibility reader`，不能把旧 artifact 转成可执行恢复状态。

# 8. 最小排查链

```text
ConversationThread + active Turn
→ TaskCheckpoint v4
→ pending assistant batch + Tool Observations
→ Operation Ledger + Approval / HumanInput
→ trace.jsonl
→ execution workspace + candidate diff
```

先确认 identity 与 authoritative state，再用 Trace 解释过程，最后检查物理 workspace 结果。

# 9. 源码入口（Source Anchors）

- `agent_forge/runtime/domain/thread.py::ConversationThread`：Thread、Turn、Run 与 Context State domain。
- `agent_forge/runtime/adapters/thread_json.py::JsonConversationThreadRepository`：journal、CAS、terminal reconcile 与 durability。
- `agent_forge/runtime/domain/task.py::TaskCheckpoint`：v4 Run recovery schema。
- `agent_forge/runtime/application/run_lifecycle.py::RunLifecycle`：checkpoint、HITL 与 terminal writer。
- `agent_forge/runtime/application/tool_execution.py::ToolExecutionPipeline`：durable batch 与 cursor recovery。
- `agent_forge/runtime/application/operation_tracker.py::OperationTracker`：side-effect state 与 fingerprint。
- `agent_forge/observability/adapters/json_trace.py::JsonTraceRecorder`：append-only trace writer。
- `agent_forge/infrastructure/atomic_json.py::atomic_write_json()`：authoritative JSON write primitive。
