# 运行产物与持久化契约

> 持久化层必须区分“用户 Conversation 真相”“当前恢复状态”“实际发生过的执行证据”和“只读展示投影”。

# 1. 四类持久化对象

```text
Authoritative Conversation
├── thread.json
└── conversation.jsonl

Authoritative Mutable State
├── context_state.json
├── terminal_intents/<turn_id>.json
├── TaskCheckpoint v4
├── HumanInput
├── Approval
├── Operation Ledger
└── Long-Term Memory

Append-only Execution Evidence
└── trace.jsonl

Derived Presentation
├── trace.json
├── usage.json
├── reports
└── Workbench views
```

`candidate_changes.diff` 是一次 Run 的候选结果，不是 Conversation，也不是恢复状态。

# 2. 写入与读取 Owner（Writer / Reader）

| Artifact | Canonical Writer | 主要 Reader | 决定什么 |
|---|---|---|---|
| `thread.json` | `ConversationThreadRepository` | Harness、Operator Console | Thread/Turn/Run 导航 |
| `conversation.jsonl` | `ConversationThreadRepository.append()` | Context、恢复、审计 | 完整 durable Conversation |
| `context_state.json` | `ConversationThreadRepository.save_context_state()` | 模型输入准备 | digest、covered sequence、Turn snapshots |
| `terminal_intents/<turn_id>.json` | `ConversationThreadRepository.prepare_turn_terminal()` | Thread loader / `finish_turn()` | 当前 Run 要提交的 terminal Turn 状态 |
| `TaskCheckpoint` v4 | `RunLifecycle` → `TaskStateRepository` | `Harness.resume()` | 当前 Run 状态和 execution cursor |
| HumanInput | `RunLifecycle.request_human_input()` | resume | 人工问题及回答 |
| Approval | `ToolAuthorizationGate` | Tool authorization | 具体 operation 是否获准 |
| Operation Ledger | `OperationTracker` | replay / crash recovery | 状态变更执行到哪一步 |
| Long-Term Memory | `LongTermMemoryService` | recall / management candidates | 带 provenance 的跨 Turn 显式记忆 |
| `trace.jsonl` | `JsonTraceRecorder` | 投影与审计 | happened-before 执行证据 |
| `trace.json` / `usage.json` | projection writers | reports / Workbench | 可读聚合，不控制 Runtime |

# 3. ConversationThread 目录

默认控制面位置：

```text
.agent_forge/internal/state/threads/<thread_id>/
├── thread.json
├── conversation.jsonl
├── context_state.json
├── terminal_intents/<turn_id>.json
└── .lock
```

`thread.json` 保存：

```text
thread identity / kind / workspace
initial_task
active_turn_id
Turn[]
└── ThreadRun[] navigation
conversation sequence / tail_hash
title / pinned / archived
```

它不复制每个 Run 的 Trace、Diff 或 usage。

`conversation.jsonl` 每行是一个 `ConversationItem`：

```text
sequence / item_id
previous_hash / item_hash
thread_id / turn_id / run_id
role / content / tool protocol fields
origin / human_authority
metadata / created_at
```

`sequence + hash chain` 证明顺序；`item_id + logical payload` 提供幂等 append。

# 4. 上下文状态（Context State）

`context_state.json` 是独立 canonical boundary：

```text
ThreadContextState
├── schema_version
├── thread_id
├── revision
├── covered_sequence
├── conversation_history_digest
└── turn_snapshots[]
```

它使用 CAS 更新。Digest 是 raw Conversation 的 derived projection；`StableTurnContextSnapshot` 是同一 Turn 跨 resume Run 复用的稳定输入契约。

# 5. 运行检查点（TaskCheckpoint v4）

```text
TaskCheckpoint
├── Identity
│   ├── run_id / thread_id / turn_id
│   └── agent_name
├── Workspace
│   ├── workspace                  requested project
│   ├── execution_workspace        actual local/worktree path
│   └── execution_mode
├── Execution State
│   ├── status / current_step
│   ├── context_revision
│   ├── last_tool / last_observation
│   ├── stop_reason / stop_output / final_answer
│   ├── resume_hint
│   └── messages_count / observations_count
└── pending_execution
    ├── assistant_item_id
    ├── next_tool_call_index
    ├── pending_operation_key
    └── pending_operation_fingerprint
```

Checkpoint 不保存：

- `Turn.root_task`；
- Conversation messages；
- Conversation digest 正文；
- Python stack 或 HTTP connection；
- Provider hidden state / KV cache。

这些分别由 Turn、Thread journal、Context State 或外部 Provider 拥有。

# 6. Follow-up 与 Resume

```text
Normal follow-up
= same Thread + new Turn + new Run

Resume
= same Thread + same Turn + new Run
```

`Harness.resume(checkpoint_path)` 校验：

- checkpoint 必须是 v4 且状态可恢复；
- Thread 与 Turn 必须存在且仍 active；
- requested workspace 必须一致；
- execution worktree 必须可重新 attach；
- frozen Turn Context contract 必须兼容。

Resume 随后优先读取 `pending_execution`，直接继续原 assistant ToolCall batch，不调用模型重新提案。

# 7. 工具批次耐久性（ToolCall Batch Durability）

顺序固定为：

```text
1. append complete assistant batch
2. persist pending cursor
3. recheck route / security / approval / operation fingerprint
4. execute or produce a deterministic non-execution result
5. append exactly one Tool Observation
6. advance cursor
```

崩溃窗口的处理：

| 崩溃位置 | 恢复动作 |
|---|---|
| assistant 已写、pointer 未写 | 从 Thread 找唯一 unfinished batch，重建 cursor |
| Observation 已写、cursor 未推进 | 只推进 cursor，不重复 Tool |
| state-changing Tool 已执行、Ledger 仍 `executing` | outcome unknown，fail closed，不重放 |
| accepted final 已写、terminal checkpoint 未写 | 复用原 final，幂等完成同一 Turn |
| terminal checkpoint 已写、Turn 仍 active | 校验 terminal intent 与 v4 checkpoint 后，幂等提交 current ThreadRun 与 Turn |

等待 Approval、Human Input 或 Pause 时不伪造 Observation，cursor 停在原调用。Terminal stop 会为所有未闭合调用写明确的 non-execution Observation。

# 8. 副作用账本（Operation Ledger）

Checkpoint 回答“Run 当前停在哪里”；Ledger 回答“这个状态变更操作执行到哪里”。

```text
planned / pending
→ approved
→ executing
→ executed | failed
```

状态变更 Tool 的 `operation_key` 绑定 normalized intent，fingerprint 绑定执行前目标状态。
批准后目标发生漂移时，旧 Approval 变 stale；`executing` 且无确定结果时不能自动重试。

只读 Tool 不依赖 Ledger 回放；状态变更、Long-Term Memory write，以及可能产生任意
workspace 副作用的 `run_command` 使用该边界。`run_command` 的 key 额外绑定 durable
assistant ToolCall invocation：同一调用恢复不重跑，新调用不会复用旧验证结果。

# 9. 运行产物（Run Artifact）

```text
.agent_forge/runs/.../<run>/
├── run_request.json
├── run_manifest.json
├── trace.jsonl
├── trace.json
├── usage.json
├── task_state/<run_id>.json
├── candidate_changes.diff
├── stop_output.txt
├── final_answer.txt                 accepted COMPLETED only
└── execution_environment.json
```

每次 Run 都有 `stop_output`；只有 accepted `COMPLETED` 才有 `final_answer` 和 `final_answer.txt`。被 output governance 拒绝的文本可以写入 Thread 作为 `model_final_candidate`，但不进入 `final_answer`。

# 10. 写入耐久性

Authoritative mutable JSON 使用：

```text
same-directory temp
→ flush
→ fsync(temp)
→ replace
→ fsync(parent)
→ cleanup temp
```

Conversation journal append 使用同一 Thread 的跨进程 `flock`：

```text
validate current chain
→ append one JSON line
→ flush
→ fsync(file)
→ atomic metadata update
```

metadata 落后于 journal 时可以从带完整 turn-start metadata 的权威 item 修复；terminal
intent 已写且对应 v4 checkpoint 已进入相同终态时，loader 会同步收口 current ThreadRun 与
Turn。metadata 超前、intent/checkpoint 身份或状态冲突、中间 hash 损坏时 fail closed。最后
一条 crash-truncated line 可截除并报告，完整 JSON 但缺 newline 时先补 delimiter 再允许后续 append。

# 11. Trace 耐久性（Trace Durability）

`trace.jsonl` 每 Run 单 writer、每 event 一行并 flush，属于 process-crash durable execution evidence。本轮不要求每 event fsync。

Reader 行为：

- 最后一条 crash-truncated line：忽略并报告；
- 中间损坏：失败；
- `trace.json`、usage 和 reports：最终从 JSONL 投影。

Trace 不保存完整 model prompt 或 raw Conversation。

# 12. Historical Evidence 边界

Production Runtime loader 只接受当前 canonical v4，不保留 v3 fallback。

冻结的 Lab / Mini-50 / Workbench raw evidence：

- 不移动；
- 不重写；
- 不重新生成；
- 不重算 hash；
- 不进入 production recovery path。

Workbench 如需展示旧 schema，只能使用独立 read-only presentation compatibility reader。它不能把旧 artifact 转成可继续执行的 Runtime state。

# 13. Workbench 边界

```text
canonical evidence
→ deterministic read-only projection
→ Workbench
```

Workbench 不补写缺失事件、不修改 Run、不为展示重新执行任务。它可以同时认识历史事件名和当前 `model_step_started`，但兼容逻辑只存在于 presentation side。

# 14. 最小排查顺序

```text
ConversationThread / active Turn
→ TaskCheckpoint v4
→ pending assistant batch / Tool Observation
→ Operation Ledger + Approval / HumanInput
→ trace.jsonl
→ execution workspace / candidate diff
```

先定位身份和 authoritative state，再用 Trace 解释过程，最后检查物理 workspace 结果。

# 15. 源码入口（Source Anchors）

- `agent_forge/runtime/domain/thread.py::ConversationThread`：Thread/Turn/Run metadata。
- `agent_forge/runtime/adapters/thread_json.py::JsonConversationThreadRepository`：journal、hash、lock、terminal reconcile 与 CAS。
- `agent_forge/runtime/domain/task.py::TaskCheckpoint`：v4 Run recovery schema。
- `agent_forge/runtime/application/run_lifecycle.py::RunLifecycle`：checkpoint、HITL 与 terminal writer。
- `agent_forge/runtime/application/tool_execution.py::ToolExecutionPipeline`：durable batch/cursor recovery。
- `agent_forge/runtime/application/operation_tracker.py::OperationTracker`：副作用状态和 fingerprint。
- `agent_forge/runtime/adapters/task_state_json.py::JsonTaskStateRepository`：checkpoint JSON Adapter。
- `agent_forge/observability/adapters/json_trace.py::JsonTraceRecorder`：append-only event writer。
- `agent_forge/infrastructure/atomic_json.py::atomic_write_json()`：强原子写入。
- `agent_forge/harness.py::Harness.run()`：Thread/Turn/Run 与 artifact 收口。
