本文汇总 NanoHarness 的核心运行规则和对应代码入口。每一行说明：什么时候触发、系统实际做什么、
失败或中断时怎样处理、由哪段代码负责。在 PyCharm 中点击“负责代码 / 运行证据”会打开本地源码文件；
旁边的 `L数字` 是精确行号，可按 `⌘L` 输入该数字到达定义。行号由测试校验。

已知能力名称、只需定位首个代码 Owner 时，使用[核心能力与代码入口](核心能力与代码入口.md)。
完整状态流与异常处理见[运行生命周期与异常处理机制](运行生命周期与异常处理机制.md)。模块依赖和类型契约见

## ToolCall 的四层处理

| 层 | 只回答一个问题 | 代码执行顺序 | 输出 |
| --- | --- | --- | --- |
| ① 入口控制 | 这是不是本轮合法的 ToolCall？ | [`ToolRouter.route`](../agent_forge/tools/tool_router.py) · `L182` 决定可见工具 → [`ToolCallNormalizer.normalize`](../agent_forge/models/tool_call_normalizer.py) · `L29` 统一成 Runtime 使用的 ToolCall 格式 → [`ToolExecutionPipeline._execute_call`](../agent_forge/runtime/application/tool_execution.py) · `L181` 确认工具已注册且属于本轮允许集合 | 接收 ToolCall；不合法时向模型返回失败 Observation |
| ② 执行决策 | 这项操作现在应不应该执行？ | [`OperationTracker.resolve_existing_operation`](../agent_forge/runtime/application/operation_tracker.py) · `L124` 查操作状态 → [`HookManager.before_tool`](../agent_forge/runtime/hooks.py) · `L235` 汇总具体规则 → [`ToolAuthorizationGate.authorize`](../agent_forge/runtime/application/tool_authorization.py) · `L59` 结合 Approval 记录与 fingerprint，决定继续、拒绝或等待 | 进入执行、拒绝、等待人工、向模型返回上次结果，或停止自动恢复 |
| ③ 受限执行 | 获得许可后，执行是否始终限制在允许范围内？ | ① [`ToolRegistry.execute`](../agent_forge/tools/registry.py) · `L41` 校验参数并调用 Tool<br>② 命令、路径和进程仍受 [`check_command`](../agent_forge/safety/command_policy.py) · `L32`、[`WorkspaceSandbox`](../agent_forge/safety/sandbox.py) · `L4`、[`ExecutionEnvironment`](../agent_forge/runtime/execution_environment.py) · `L75` 约束 | Tool Observation；越界时返回拒绝原因 |
| ④ 结果与恢复 | 发生了什么，中断后从哪里继续？ | [`HookManager.after_tool`](../agent_forge/runtime/hooks.py) · `L285` 处理并脱敏 → [`OperationTracker.record_execution_result`](../agent_forge/runtime/application/operation_tracker.py) · `L340` 提交 executed/failed → [`RunLifecycle.update_checkpoint`](../agent_forge/runtime/application/run_lifecycle.py) · `L70` 保存恢复点 | 脱敏后的 Observation + 操作状态 + Trace + Checkpoint |

四层依次回答：**调用是否合法 → 当前是否允许执行 → 执行是否始终限制在允许范围内 → 结果是否已记录且可恢复**。Approval 只参与第二层，不能绕过第一层或第三层。

### Pause / Cancel 的三个到达时机

| 信号何时到达 | 当前行为 | 设计原因 |
| --- | --- | --- |
| ① 模型或 Tool 尚未启动 | 处理信号，不启动下一项调用 | 此时没有正在执行的外部操作，可以直接停止 |
| ② 模型 Provider 的 HTTP API 请求已发出 | 等请求返回并记录 Usage/Trace；旧响应不再用于生成最终答案或触发 Tool，随后暂停或取消 | 中断客户端连接不能证明 Provider 未执行或未计费 |
| ③ ToolGateway 命令已在进行 | 等命令返回，保存脱敏后的 Observation、操作状态和 Checkpoint，然后停止 | 避免部分写入、残留子进程，以及操作长期停在结果未知的 `executing` |

## 职责不同、不能互相替代的概念

- 重复 ToolCall 判断模型是否原地打转；连续工具失败保护限制连续失败次数；操作状态表记录持久状态变更是否已执行。
- Hook 提供生命周期时机，具体处理器给出允许、拒绝或询问人工的判断，Gate 决定继续、拒绝或等待，Trace 记录事件，Checkpoint 保存恢复状态。
- operation key 判断是不是同一操作；fingerprint 判断目标是否变化；操作状态表记录执行进度。
- Batch 决定哪些 Task 可同时运行，Patch 表示 Worker 产生的候选改动，Coordinator 负责合并，Finalizer 只读验收。
