# 运行治理与工具执行

> 模型提出 ToolCall；Runtime 决定本步可见工具、具体调用是否获准、副作用是否已经发生，并把每个调用收口成唯一可恢复的 Observation。

# 1. 主链

```text
AgentResponse(content + ToolCalls)
→ ToolExecutionPipeline.execute_calls()
→ ConversationItem(role=assistant, complete batch)
→ TaskCheckpoint.pending_execution
→ ToolExecutionPipeline._continue_pending_batch()
→ ToolExecutionPipeline._execute_call()
    → current control / route / guardrail checks
    → OperationTracker.build_operation_intent()
    → OperationTracker.resolve_existing_operation()
    → ToolAuthorizationGate.authorize()
    → side-effect ledger: approved → executing
    → ToolExecutionPipeline._run_tool()
    → ToolGateway.execute()
    → HookManager.after_tool()
    → OperationTracker.record_execution_result()
    → ToolFeedback.append_tool_observation()
→ ConversationItem(role=tool)
→ advance pending cursor
```

```text
Model proposes
Runtime controls side effects
ConversationThread records protocol truth
Checkpoint points to unfinished execution
```

一次调用成功后，Observation 进入 Thread 和 Run-local view，下一 Model Step 基于结果继续规划。等待人工、暂停、失败和终态都在同一控制链上显式收口。

# 2. 完整 Assistant Batch 的持久化边界

一个 provider response 可以同时包含 assistant content 与多个 ToolCalls。`execute_calls()` 先保存完整 response，再开始任何调用：

```text
provider response
→ preserve complete assistant content and ToolCalls
→ append to conversation.jsonl
→ persist PendingExecutionPointer
→ execute calls in original order
```

`PendingExecutionPointer` 保存 `assistant_item_id` 和 `next_tool_call_index`，必要时再绑定 pending operation identity。预算裁剪、人工屏障或 terminal stop 只改变调用的 execution disposition，不改写模型已经提出的 batch；不执行的调用也会形成明确的 non-execution Observation。

# 3. 三个治理 Owner

| 边界 | 决策 | Canonical Owner |
|---|---|---|
| Routing | 当前 Model Step 暴露哪些 Tool schemas | `ToolRouter.route()` |
| Authorization | 这次具体调用是否可执行 | `ToolAuthorizationGate.authorize()` |
| Dispatch | 已获准调用交给哪个实现 | `ToolGateway.execute()` / `ToolRegistry` |

`ModelStepPreparation.prepare_model_step()` 从同一个 `ToolRoute` 取得 `schemas + allowed_names`。执行时重新核对 `allowed_names`，随后再处理 arguments、scope、Approval 和 side-effect policy。Tool visibility 与 concrete-call authorization 是连续但独立的控制点。

# 4. Operation Intent 与 Approval

`OperationTracker.build_operation_intent()` 把可能产生副作用的调用规范化为：

```text
tool identity
+ normalized target and action
+ side-effect semantics
→ operation key + fingerprint
```

Operation Ledger 状态是：

```text
planned
→ pending / approved
→ executing
→ executed / failed
```

| Existing state | Runtime action |
|---|---|
| `executed` 且 fingerprint 相同 | 复用 durable result |
| identity 相同但 fingerprint 漂移 | 原授权和结果视为 stale |
| `executing` 且无 durable result | outcome unknown，停止自动 replay |
| 无已发生副作用证据 | 继续 authorization 与 execution |

只读 Tool 不创建 durable operation record。Workspace mutation、Long-Term Memory write 和可能产生任意 workspace effect 的 `run_command` 进入 Ledger。

`ToolAuthorizationGate.authorize()` 汇合 execution environment、permission hooks 和 Approval policy：

```text
DENY → rejected Observation
ASK  → durable ApprovalRequest + waiting_approval
ALLOW → continue; side effect has not happened yet
```

Approval 与 operation fingerprint 绑定。目标漂移后需要重新决策。

# 5. 执行与唯一 Observation

`ToolExecutionPipeline._run_tool()` 是唯一执行出口：

```text
last terminal-control check
→ side effect: record approved / executing
→ ToolGateway.execute()
→ HookManager.after_tool()
→ record executed / failed
→ update WorkingMemory / Evidence / Trace / Checkpoint
→ append durable Tool Observation
```

Raw Observation 先经过 after-tool hooks 和 secret redaction，再成为 Runtime 内部各 projection 共同消费的 final Observation。每个 ToolCall 最终对应且只对应一条合法 Observation：正常结果、argument error、DENY、Approval rejection、replay、budget skip 和 terminal skip 都使用同一个协议出口。

处于 `waiting_approval`、`waiting_human` 或 `paused` 时，当前调用尚未形成结果，cursor 保持在原位置；same-Turn resume 后继续。

# 6. Human authority 与显式 Memory write

`ask_human` 在 batch 内建立排他屏障。Runtime 先持久化问题并停止，真实回答到达后 raw journal 保持 authority-first 顺序：

```text
human/operator item with human_authority=true
→ Tool Observation closing ask_human
```

Provider 协议要求 Tool result 紧跟 ToolCall，因此 `load_transaction_safe_conversation_page()` 只读投影为：

```text
assistant ToolCalls
→ all Tool Observations
→ authoritative human answer
```

Raw journal 不被重排。Provider `role=user` 只表示消息编码；Runtime authority 由 `origin + human_authority` 确认。

`remember_memory` 使用窄授权链：

```text
current Turn human-authority item
→ exact source_quote match
→ current Model Step management candidates
→ CREATE / UPDATE / NOOP validation
→ LongTermMemoryService
```

该调用不会从历史 Turn、Worker coordination 或模型文本派生新的用户授权。

# 7. 崩溃恢复（Crash Resume）

`ToolExecutionPipeline.resume_pending_calls()` 读取 v4 checkpoint 和原 assistant item，不调用模型：

```text
TaskCheckpoint.pending_execution
→ get original assistant item
→ restore ToolCalls + original route metadata
→ current registry may narrow executable set
→ continue from next_tool_call_index
```

关键 crash windows：

| Durable facts | Resume action |
|---|---|
| assistant item 已写，pointer 未写 | 从同 Turn 唯一 unfinished batch 重建 cursor |
| Observation 已写，cursor 未推进 | 只推进 cursor |
| Ledger 为 `executing`，result 缺失 | 标记 unknown outcome，不重复副作用 |
| pointer 指向尚未执行调用 | 重新经过 current control、guardrail、authorization 与 replay checks |

Tool item identity 绑定 assistant item、batch index 和 provider ToolCall ID，避免跨 Model Step 的 ID 重用产生冲突。

# 8. 失败与信任边界

```text
Untrusted Model ToolCall
→ route / schema / guardrail
→ authorization / approval fingerprint
→ side-effect ledger
→ execution environment
→ external effect
→ typed and redacted Observation
→ Thread protocol truth + Run evidence + next model input
```

Decision hooks 失败时 fail closed；after-model/after-tool 等变换或通知 hook 的失败会记录并隔离。Validation 命令返回失败是任务反馈，Provider/permission/arguments/unknown side effect 等 Runtime failure 保持独立分类。

- `agent_forge/runtime/application/model_step_preparation.py::ModelStepPreparation.prepare_model_step()`：schema 与 allowed names 的共同路由入口。
- `agent_forge/runtime/application/tool_execution.py::ToolExecutionPipeline.execute_calls()`：完整 assistant batch 与 cursor。

- `agent_forge/runtime/application/tool_execution.py::ToolExecutionPipeline._execute_call()`：单次 ToolCall 治理主链。
- `agent_forge/runtime/application/tool_authorization.py::ToolAuthorizationGate.authorize()`：Hook 与 Approval 收口。
- `agent_forge/runtime/application/operation_tracker.py::OperationTracker`：side-effect identity、replay 与 Ledger。
- `agent_forge/runtime/application/tool_feedback.py::ToolFeedback.append_tool_observation()`：唯一 Observation persistence。
- `agent_forge/runtime/application/session.py::load_transaction_safe_conversation_page()`：raw authority 到 Provider-valid projection。
